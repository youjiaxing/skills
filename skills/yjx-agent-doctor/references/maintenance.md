# 扩展与维护

仅在用户要求维护本skill、增加Agent适配或沉淀问题案例时读取。

## 文档归宿

- 跨平台都需要的决策与执行边界保留在 [SKILL.md](../SKILL.md)。
- 具体Agent的运行环境、配置语义和取证位置放在 `agents/` 下；从入口增加明确的按需读取条件。
- 真实问题的证据与修复放在 `cases/` 下，并更新[案例索引](cases/index.md)的症状或预检线索。一份事故包含不同问题时，可用多个索引入口指向同一记录，不复制正文。

只有出现真实适配或案例才增加文件；无需为计划支持的每个Agent创建空目录或占位说明。新增适配不能将一个版本的工具名、配置位置或协议结论强加给其他平台。

## 案例应保留什么

记录足以判断是否适用及如何恢复的信息，未知项明确标注：

- Agent、运行时版本、模型的请求/配置/实际身份和服务路径；区分观察时间与版本适用范围。
- 可观察症状或静态失配依据，及可定位的脱敏证据；不能只保留结论。
- 已确认机制、未确认解释、必要前提和排除条件。
- 精确修复差异、影响、备份/回滚、生效条件及替代措施。
- 实际验证过的组合、结果、验证时间和限制；未经验证的推广保持推断。

公开记录去掉凭证、账号、私人业务内容和机器专有路径。以当前可验证的版本支持范围为依据；案例过时或被新证据推翻时更新或移出适用索引，不继续推荐原修复。

## 维护验证

检查名称/元数据/目录及入口一致性、所有相对引用和案例路由，并独立静态审阅实质设计变化。只把有当前证据的案例列为可用依据，不建立按品牌猜测的兼容矩阵。

遵循仓库维护规则：提示文档采用静态审阅、一致性及打包/链接检查，可回顾真实用户交互。不要创建、保留或运行模拟会话行为测试，包括合成对话、脚本角色扮演和模型/Mock驱动的提示词行为评测。可执行脚本的实际功能测试仍可进行；这些检查不证明skill提示词能可靠地产生预期行为。
