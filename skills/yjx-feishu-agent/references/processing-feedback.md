# 原消息处理反馈

所有已授权群内、通过白名单及明确 @ 校验的请求，标记都加在本次用户消息上。引用的推送消息不变。

| 表情 ID | 含义 |
| --- | --- |
| `OnIt` | 已持久受理，可能排队或处理中，不表示 Codex 已开始执行 |
| `DONE` | Codex 已完成，且最终回复的飞书消息 ID 已落盘 |
| `CrossMark` | 需关注：请求受阻、失败、中断，或执行/回复结果尚未确认 |

先添加当前结果标记，再独立核对和移除本功能创建的旧标记；旧 unknown 查询或清理失败不阻止新标记。标记在后台尽力更新，独立 HTTP 请求最多 3 秒，包含取令牌或分页的时间；它不延迟 Codex 或最终回复，也不保证固定展示时限。缺权限或网络异常可能导致缺失、旧标记残留或暂时并存，不能仅凭表情决定重发任务。

标记读写分别需要 `im:message.reactions:read` 和 `im:message.reactions:write_only`（或接口允许的替代权限），机器人须在群内。缺权限时保留原消息收发，记录不含密钥/消息正文的 `feedback-warning`；不自动扩权。普通表情操作参考已安装的 `lark-im`。

状态保存在仓库外 `feishu/<app hash>/feedback`，与 `messages` 任务日志分开。只管理本功能创建并记录的 reaction ID；其他人或预先存在的机器人表情不清理。添加回执未知时保留未知状态，仅通过只读查询核对；无法唯一归属时不重复添加。删除结果未知时不盲重试。

重启按本功能版本标识扫描任务记录，凭已落盘的 Codex 完成状态和最终回复 ID 恢复标记；证据不足转为需关注，不重新执行或发送回复。已完成回复后的来源登记失败仍可标记完成，路由故障需另查。升级前历史请求不补标。

T3 入站以原消息上的 `OnIt` 为正常受理反馈；表情已确认时不另发排队文字。表情未成功时，仍在取证确认任务运行中后兜底回「还在处理，有结果会再回。可以继续发新消息。」，避免重复提示。失败、中断、受阻或未提交回「这次没答上。」；即使已加 `OnIt`，终态失败也必须发送。等待补充或授权回「还在等补充信息或授权，有结果会再回。可以继续发新消息。」最终答案独立回复。这些文案不带请求编号。受理拒绝仍用「本次消息未受理（…）」，同样不含编号。文字发送失败以原消息 CrossMark 兜底。状态反馈、答案、来源登记分别记账，已受理说明不能触发 DONE。投递与观察独立于新请求提交，单次异常不锁住后续使用。

T3 新账本的待投递在服务连接恢复后继续处理，同一投递沿用冻结正文和稳定 UUID；回执未知重试限于飞书一小时的幂等有效期，过窗保留待核查，不盲重发答案。待反馈及核查编号在 `receiver.mjs status` 的 delivery 摘要和 `diagnose-message.mjs` 中可见；本机记录不等于用户已收到。恢复按最新状态和反馈版本收敛，过时且尚未发出的状态不补发。原生 Codex 适配仍保留已经尝试回复但结果未知时不自动重发的行为。

Agent 在正常问答中输出正文，由接收器负责这些反馈，不额外手动维护表情或另发一份答案。
