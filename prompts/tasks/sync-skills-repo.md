# Skills 仓库同步与新增技能安装

在宿主指定的本项目仓库中完成自动提交、合并远端更新、推送及新增 Skill 的本机安装。遵守根 `AGENTS.md`；目标为 `main` 与 `origin/main`。时间和会话设置以宿主调度为准。

## 同步仓库

1. 核实实际工作目录、分支、工作区、Git 操作状态及其他任务的写入范围。正在进行的其他工作需要先核实归属，避免切换分支或把未完成工作混入提交。
2. 将全部属于本次同步范围的未忽略改动（新增、修改、删除）暂存并提交；无改动跳过提交。提交信息按 `<type>(<scope>): <中文摘要>`，依据实际差异提炼。
3. 拉取并合并 `origin/main`。遇到冲突时，读取冲突文件、双方改动及必要历史，按改动意图保留双方有效内容，完成合并或已经进行的 rebase；不要机械整批选用一侧。执行与实际改动相适应的验证。
4. 推送 `main`。远端新增提交导致推送被拒绝时，重新拉取、合并、验证并推送。

遇到故障主动诊断，修复权限内可处理的问题并重试。清理锁文件前确认没有活跃 Git 操作，且锁确属残留。不强制推送、不丢弃工作、不绕过仓库校验。持续处理到同步完成；仅在凭据、权限、必要业务信息等经诊断仍无法安全解决的真实阻塞下保留现场并说明。

## 安装新增 Skill

每次合并远端更新后，核对 `skills/` 直接子目录中含 `SKILL.md` 的有效 Skill 及本机安装状态；既检查本轮新增项，也检查此前安装失败或漏装的项，不只依赖本次 Git diff。

- 在仓库根使用现有 `node scripts/link-skills.mjs status` 检查状态。按输出识别缺失链接或原生挂载，向用户仅汇总计数、技能名称与异常，不倾倒完整链接清单。
- 有新增或未安装 Skill 时执行 `npm run link`，复用 `developer-targets.local.yaml` 已启用的 Agent 目标与仓库的原生挂载机制。已有正确链接直接复用，不另行下载相同 Skill 的独立副本，不改本机目标选择。
- 同名路径冲突时先核查归属；保留无关安装和文件，不能用 `--force` 或 `--prune` 绕过冲突。仅在现有授权及证据足以安全处理时修复；否则报告具体阻塞，不能声称安装完成。
- 安装后再次执行 `node scripts/link-skills.mjs status`，核对所需目标已正确链接或挂载。若安装失败而 Git 同步仍可安全完成，完成同步并单独报告安装失败；后续运行继续检查缺失项。

## 结果

用中文报告提交、拉取、冲突及故障处理、验证、推送结果，以及新增或补装 Skill 的名称、安装与回读结果、剩余阻塞。区分配置或文件链接已生效与当前宿主会话是否已重新加载技能；不要为了验证安装擅自执行新 Skill 的业务。

需要子代理调查或独立评审时，沿用宿主当前可用模型设置。Start every subagent with a fresh context window (do not fork the current conversation).
