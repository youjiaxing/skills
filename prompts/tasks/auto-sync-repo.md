# 仓库自动同步任务指令

对当前 `skills` 仓库进行日常定时同步（包含暂存提交、拉取更新与推送），并在冲突时安全消解。

## 执行前检查

1. 确认工作目录位于当前项目仓库根目录（`/Users/youjiaxing/Code/youjiaxing/skills`）。
2. 执行 `git status --porcelain` 检查本地工作区状态。

## 执行步骤

### 1. 本地提交（如果有需要提交）
- 若工作区存在修改（包含未跟踪文件）：
  1. 执行 `git add -A` 暂存所有工作区修改。
  2. 根据实际 `git diff --cached` 提炼符合 Conventional Commits 规范的语义 Commit Message（例如 `fix(module): ...` 或 `sync: update ...`）。
  3. 执行 `git commit -m "<提炼的提交信息>"` 完成本地提交。
- 若工作区干净无修改，跳过本步直接进入拉取环节。

### 2. 拉取远端更新
- 执行 `git pull --rebase origin main` 拉取远端更新。
- **若顺利快进或自动变基成功**：直接进入步骤 4。
- **若产生冲突**：进入步骤 3 冲突安全消解流程。

### 3. 冲突安全消解与回滚机制
- 检视冲突文件（`git status --short` 中标为 `UU`、`AA` 等状态的文件）。
- 分析本地与远端双方改动意图，进行语义合并：
  - 属于非排他性内容（如并行的功能扩充、不同条目、文档追加）时，完整保留双方有效变动并清除冲突标记。
  - 属于同一行或排他性逻辑改动时，评估上下文合理性；若能明确逻辑从属，完成意图对齐合并。
- 合并后执行基本静态检查：
  - 执行 `git diff --check` 确保无残留冲突标记或空白错误。
  - 对 Markdown/提示词文件确认语法完整；对修改的代码脚本运行对应模块测试或语法检查。
- **判定与分支处理**：
  - **校验通过**：`git add <冲突文件>`，然后执行 `git rebase --continue`，直到变基完成。
  - **无法保证正确性 / 校验失败**：立即执行 `git rebase --abort` 终止变基，保留本地修改，向用户输出包含冲突文件与排查建议的告警通知，**严禁强行推送**。

### 4. 推送到远端
- 检查本地是否超前远端（`git status` 或 `git cherry -v`）。
- 若本地存在待推送提交，执行 `git push origin main`。
- 若无需推送，保持现状。

### 5. 简短报告
- 简明汇报执行结果：
  - 本地提交记录（若有提交，注明 commit message 与哈希）。
  - 远端拉取状态（快进 / 变基成功 / 本地已是最新）。
  - 冲突处理情况（无冲突 / 语义消解完成 / 无法判定并安全回滚）。
  - 推送状态。
