# Agent 推理测试

考官负责调度、取证和评分；被测方独立作答。用户用自然语言说明模型、题目和测试模式，内部命令及配置由考官处理。

## 1. 确认本轮范围与入口

用户可以说“测一下 Opus 的糖果题”“对比这几个模型的全部题”或“再做一次鹈鹕题”。从当前对话复用已经确认的信息，只追问缺失的模型、题目或模式；未指定题目时先确认范围，不能静默只测糖果题。开始前简述本轮模型、题目、次数和总调用量。

- 随手测：所选题目各一次。
- 正式对比：糖果题每模型三次，鹈鹕题每模型一次。
- 第一版只有两道原题；变体与历史成绩对比不在本轮范围。

先用宿主的 Provider 能力目录确认模型与设置，再遵循宿主的子代理路由规则。T3 Code 中保留父子关联及可打开的子会话链接。模型不可用、限流或调用失败时报告具体状态；不自动切换 Provider、改模型、换成本地 CLI 或增加重试次数。

本地 CLI 仅在用户明确选择该路径时使用，执行前说明“本地进程，不生成可见 T3 子会话”。兼容层的 `claude | codex | gemini` 限制不约束宿主 Provider 目录；模型名前缀不能作为 Provider 路由依据。

入口诊断只输出白名单元数据：Provider ID、模型 ID、支持状态及去除凭据后的服务 origin。需要读本地配置时定点解析所需字段，经 `scripts/safe-output.mjs` 投影后输出；不打印配置全文、环境变量值、原始异常或用字段名黑名单过滤。原始被测记录保存到私人运行目录，终端和报告只显示必要引用与已净化状态。

## 2. 固定题面并派发

每次派发处执行：**Start every subagent with a fresh context window (do not fork the current conversation).** 宿主支持隔离参数时显式选择不继承父对话；T3 委派仅使用任务上下文。用户已确认只需上下文隔离，使用共享工作区即可，不创建 worktree。记录宿主实际提供的隔离证据；系统提示和全局说明是否存在另行如实说明。

只发送 [统一作答约定](bank/instructions.md) 加所选题目的原文：[糖果题](bank/candy/question.md) / [鹈鹕题](bank/pelican/question.md)。保存这两段实际发送文本及 SHA-256；宿主自动添加的包装另行记录。评分要点、标准答案、其他作答和考官历史不传入。不得现场添加部件清单、解题提示或改写题目；题面有变更即使用不同版本，不混合计算成绩。

被测方只在最终回复中作答，不调用工具、读文件、联网、使用 Skill/MCP 或再委派。提示约束不是工具硬禁；是否存在硬禁能力和实际工具调用分别登记。对于未声明题意，先明确“参与者可选择什么、对手可决定什么”再建立核验模型；脚本验证形式化模型，不代替题意判断。

派发返回后保留任务与子会话标识。严格遵循宿主返回的等待/唤醒指令；收到完成通知后读取完整活动及终态，不只取最终摘要。缺失区段、分页或截断尚未补齐时保持“未审计”。

## 3. 保存运行证据与判卷

产物统一写入 `~/.yjx-agent-iq/runs/<本轮目录>/`，每次运行独立保存 `prompt.txt`、原始记录、最终作答、审计与评分、子会话链接及模型设置。用 [内部证据接口](references/evidence.md) 整理宿主记录并调用脚本；读取旧产物只用于本轮明确要求的更正，不纳入新的模型成绩。

运行状态、审计状态和答题状态分别记录：调用失败/超时/无最终答案记“未完成”，不送判卷；发现实际工具或外部调用记“违规作废”，不计分；覆盖不全记“未审计”。记录未知协议时保留未知，不能把“JSON 能解析”当成完整审计。

### 糖果题

考官先从最终作答中确认最终数字，并引用原文；`scripts/score-candy.mjs` 只验证引用存在和数字是否等于 21，不用关键词推断最终结论。按 [评分依据](bank/candy/key.md) 判断形状选择权、21 颗保证方案及任意 20 颗配额均不能保证成功的证明，接受等价论证。每项附作答原文和理由；缺少或不确定的证据记 `review`，明确错误记 `fail`。数字和全部论证通过才记 `pass`。

### 鹈鹕题

保留被测方原始 HTML。`scripts/validate-pelican.mjs` 只提供语法/引用线索；圆形数量、命名和动画标签不能证明画面有正确部件或动作。缺少完整文档记“未完成”；外部依赖和运行错误需结合浏览器证据确认，静态扫描未发现引用不等于已证明无网络请求。

视觉验收读取 [证据与画面标准](bank/pelican/rubric.md)：在宿主浏览器实际运行原文，保存控制台/网络证据；按明确的动画时间点覆盖关键相位。按名称发现并调用已安装的 `yjx-image-reading`，复用其准备与只读观察流程。视觉派发处执行：**Start every subagent with a fresh context window (do not fork the current conversation).** 观察者一次收到本次问题所需帧与时间点，返回逐项观察及不确定性。

预览器要求改高度等适配时保留独立副本、变更说明及两份哈希；适配副本的成功不能冒充原文运行通过。工具自动回图导致主会话已收到图片时如实披露，不能事后声称视觉上下文已隔离。缺少隔离读图、原文运行证据或关键相位时，相关条目保持待复核，不补做没有授权的新模型调用。

## 4. 交付与结束

用脚本汇总本轮计划次数、完成、通过、失败、违规、未审计和待复核数；失败与限流也显示，不能从汇总中消失。交付 `report.md`、每次作答及证据链接；鹈鹕题同时生成 `gallery.html`，用隔离 iframe 播放原始产物，由用户终审视觉效果与排名。人工复核未完成时报告实际位置，不能宣称整体通过。

结论只描述本题、本版本和本次设置下的表现。一次样本、用户选择的成本方案或脚本结构检查，均不证明“智商”、背题、稳定区分度或变体更难。历史更正追加评估记录并保留原作答、子会话与先前评估，区分历史观察和本次重判。

内部脚本由考官执行，使用方式见 [内部证据接口](references/evidence.md)，不要求用户记忆命令或维护 YAML。
