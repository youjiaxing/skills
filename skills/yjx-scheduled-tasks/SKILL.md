# Agent 定时任务

使用宿主已有调度能力完成用户请求。首版覆盖 Agent 宿主定时任务，不管理 cron、launchd 或系统任务计划程序。

评审或修改本 skill 时读取 [MAINTENANCE.md](MAINTENANCE.md)；普通执行无需加载。

## 1. 核实目标与操作范围

根据用户请求确定创建、修改、整理提示词或恢复哪项任务，以及所属项目和实际执行位置。读取适用项目规则，检查 Git 状态并保留已有改动；使用当前宿主提供的任务查询与调度接口，按需核实目标机器的可访问能力。

核对任务是否需要模型逐次参与。对于采集、转换、比较或启动既有命令等确定性步骤，优先评估由已有脚本与调度承担正常执行，将模型保留在需要判断、解释或异常处理的节点；结合执行频率、维护成本及可靠性决定是否值得调整。涉及系统调度的方案可提出建议，迁移与配置交由具体项目按对应授权另行实施。

修改或恢复前核对可见的现有任务，结合任务标识、项目与内容确定目标，不仅凭同名判断。已有任务优先原位更新；整理提示词时保留原有周期、启用状态、会话绑定及其它无关配置。

用户明确要求配置任务时，在该范围内继续操作，无需逐步重复确认；仅讨论时先给方案。缺失信息会影响执行对象、时间含义或操作权限时才澄清。宿主能力或访问不足时报告具体限制，不自行改装其它调度系统或扩成多机器巡检。

*完成条件：目标、允许的操作和宿主能力已核实；目标歧义及有后果的缺失信息已解决。*

## 2. 选择任务内容的真源

先查找已有 skill、脚本和项目任务文档，按以下规则组织：

- **已有入口覆盖任务：** 直接引用。技能按注册名通过宿主发现机制定位；项目文件沿用所属项目的路径约定。缺少入口时报告，不猜安装路径。
- **指令需要长期维护或重要且难以重建，现有入口未覆盖：** 将尚无权威归属的任务意图、执行指令和结果要求保存在任务所属仓库，沿用已有目录习惯；无约定时可用 `prompts/tasks/<任务名>.md`。共用规则只引用已有真源。
- **简单、短小且易于重建：** 可以直接内联，无需为每项定时任务创建文件。

修改已有入口前，核对已知调用方及共享范围。共用规则仍在原入口维护；任务独有要求通过必要参数或任务专属入口表达。影响请求范围之外的调用方时，先说明影响并取得对应授权。

周期、时区、启用状态及会话绑定等调度配置留在宿主中，不另建版本化清单或复制进任务正文。工作目录、工具和账号状态按需现场核查；项目已有依赖与运行说明直接引用，只有必要且未记录的特殊前提才补到对应项目文档。

需要编写或整理 Agent 文档时，先通过宿主发现机制定位并读取 `writing-for-agents`，从其安装位置解析参考；依赖不可用则报告并保留已完成的调查。持久化内容须适合所属仓库的可见范围，秘密通过现有安全配置提供。无仓库或内容不宜存入当前仓库时，先查已有合适持久化位置；位置仍不明确时询问，不另建备份体系。

任务文件应位于可纳入版本管理的位置，检查是否被忽略，并在交付时如实说明尚未提交等保存限制。文件落地不自动授权 commit、push、创建远端或跨机器同步。

*完成条件：任务内容有明确真源，需保存的独有指令已落地，已有规则和调度配置没有被复制成平行真源。*

## 3. 配置触发入口

使用复用或持久化入口的任务，调度提示词只保留入口引用和本次必要参数，例如“读取 `prompts/tasks/<任务名>.md` 并执行”或“调用 $<技能名>”。示例中的名称和路径必须替换为已核实的实际入口，不在提示词中重述完整流程或固化本次会话的模型设置；上节允许内联的短任务直接使用精简指令。

配置前核对实际执行上下文能否解析入口：技能是否可发现、项目路径从哪里解析、执行位置是否能读取源文件。优先用注册名或仓库相对路径，仅在宿主确需时使用实际绝对路径。当前会话可读不等于未来调度已验证；无法核实时说明具体缺口，不复制全文到调度器补偿。

通过宿主接口写入用户要求的调度设置。恢复丢失任务时，依据现有入口或保存的指令补齐当次必要设置；周期等已丢失且无可靠信息时向用户确认，不编造历史配置或缺失正文。恢复依靠指令真源，不依赖本 skill 保存调度备份。

写入失败或回执不明时，先查询实际状态再决定是否重试；状态无法核实时保留未知，避免重复创建。只配置任务不附带立即运行其业务；用户要求试跑时，另按实际任务的操作权限执行。

*完成条件：请求范围内的配置已保存并可核对，或已明确报告失败、状态未知及其影响。*

## 4. 回读并交付

通过宿主返回的实际配置或查询接口核对任务标识、项目、入口、调度及本次要求保留的设置。说明完成的是配置核对、入口读取还是实际运行验证；创建成功不能证明业务执行成功。

简要交付任务的实际变更、源文件或复用入口、保存状态、下次运行时间（宿主提供时注明时区），以及未完成范围。记录维护所必需的信息即可，不再生成一份完整调度档案。

*完成条件：用户能找到任务内容、了解实际配置结果与验证边界；失败或未核实部分未被宣称完成。*
