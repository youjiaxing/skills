# 攻略资料与呈现

## 选择交付方式

基础攻略按片区、主题或体验类别组织，帮助读者判断值得去、吃、玩什么及是否适合自己。先整理实际来源中的内容，再沉淀地点与体验；仅搜集资料时停留在这个层级。用户要求编排本次顺序时，再使用 [行程攻略交付结构](planning.md#攻略交付结构) 形成时间表与路线，关联既有资料。日期是否确定不代替这项范围判断。

## 组织可读内容

先明确攻略要服务的体验。用户提供的社媒帖子、视频或榜单是发现入口，不是本次攻略的范围上限：它提到吃什么、看什么，就以这些名称为起点，调用 `yjx-life-query` 查当地近期实探、评价和媒体材料，找出可导航的具体店铺、分店、招牌菜、营业与排队条件，再与用户已给的地点一起取舍。用户特别重视吃喝时，吃什么、在哪里找和如何选择是基础攻略的重要内容；编排行程后再关联当天的用餐安排，不能只复述原帖，也不能因原帖没给店名就停止检索。

吃的名称先分成两类写：能核到具体门店或固定位置的，给导航入口和明确的“点什么”；只有品类、画面或无名摊位的，写清来源已支持的寻找方式、售罄条件和替代，不能把评论里的名称补成已确认门店。基础攻略保留有价值的候选、差异及待核线索；编排单次行程时，才将相关候选落实为“吃、替换或明确跳过”，并关联当天安排。

**就地呈现证据。** 在各门店、食物和地点条目旁保留支持该条目的可追踪原帖或原视频链接；有可用实拍图片或视频画面时，尽量直接展示并标注作者、来源和对应内容。视频链接带具体时间点，先核对时间点确实对应所述内容；实测跳转效果，并区分未实测或平台不支持的情况。画面、价格、体验评价标明拍摄或发表时的口径，不推断为当日事实。无法取得原帖链接或准确时间点时，在该条目说明缺口，不用搜索首页、无关图片或猜测时间替代。来源清单可补充完整资料，但不能代替条目旁的入口。

地点与体验条目写出来源支持的特色、具体内容、适用条件与取舍，让读者不跳转原文也能作出初步选择。地点入口直接使用 `yjx-life-query` 的双平台交付结果，其缺口按查询 Skill 的规则处理。经验、实用技巧和避坑从查询 Skill 的结构化信息中引用到相关条目或时段旁，保留作者口径与影响适用性的条件。

信息价值决定收录，来源决定配图要求，具体提取与身份核验使用查询 Skill 的来源交接规则。无图但有具体依据的文字条目正常呈现；可用实拍帮助理解内容，图片缺失不单独决定体验价值。影响选择的未知就地说明，内部提取状态和查询过程留在资料维护面，不作为读者页面的骨架。

按用途选文字分组、列表、画廊或筛选视图；保留现有有效组织方式，不预设数据库数量或固定字段清单。场所、体验和经验可独立关联，普通浏览只显示当前需要的内容；完整资料总表、过时行程和维护入口按授权整理，避免在阅读流中重复堆叠。

## 资料保存与复用

在本次已授权的目标页面或资料范围内保存；探索材料先留在任务范围，不自动进入全局地点库或长期档案。复用既有数据结构，以属性、关联或结构化摘录承载经验项及其来源，不因需要结构化就另建数据库。经验的具体字段与信息性质沿用 `yjx-life-query` 的来源交接结果，避免在正文和属性中维护两份完整副本。

结构化摘录作为日常读取入口；完整原文/字幕独立保存到正常读取攻略或摘录时不会连带返回的位置，并保留可访问引用及已读范围。Notion 折叠只改变界面展示，不能单独保证全文不被工具返回；选择独立页面或文件后，回读摘录入口确认实际返回范围。再次取证按查询 Skill 的复用规则进行。

改变资料布局前读取现有记录、关联和嵌入视图，区分库本体与链接视图；清理旧入口时保留仍需使用的资料和引用。删除、移库或改写遵守当前授权，不因优化阅读布局扩大范围。保存后回读条目、经验关联、来源入口、图文对应和全文引用，确认摘录可独立使用；明确报告局部失败。
