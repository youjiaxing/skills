# 访问门禁与登录态判定

本文件是登录、验证与画质门禁的唯一规则来源；其他参考按需引用此处，不另立门禁。

## 硬门禁

访问任一请求来源的视频、字幕、播放器或相关页面时，若遇到需要用户亲自完成的登录、反机器人验证、年龄确认、地区或付费权限，而当前浏览器环境未保持有效状态：

1. 立即停止本次任务的取证、编译和外部写入；
2. 告知用户需要在**当前内置浏览器**中完成登录或验证，并等待确认；
3. 等待期间保持同一请求中的其他来源暂停，保持该来源待核验状态，不使用转载、搜索摘要或其他未授权替代来源；
4. 用户确认后，从该来源的最终页面身份重新核验并继续。

## 浏览器绑定与宿主差异

- **“当前浏览器”的定义**：仅指宿主提供的内置浏览器（例如 Codex Desktop 通过 `mcp__cua_repl` 等宿主工具绑定的内置浏览器标签）。普通外部 Chrome 扩展会话、Chrome DevTools MCP、独立 Playwright、外部 HTTP 和命令行匿名请求只作诊断，不作为最终截图来源或登录态依据。Bilibili 等平台允许匿名与已登录请求返回不同画质和字幕字段，外部请求缺乏浏览器 Cookie 属正常差异。
- **宿主没有内置浏览器时**：不存在可供判定的“当前浏览器”。登录态一律记为 `browser_session_unverified`，匿名结果一律记为 `anonymous_request`，直接按 [无浏览器 / 非 macOS 降级路线](source-adapters.md#无浏览器--非-macos-降级路线) 继续，不要求用户登录，也不把匿名缺失写作“不存在”。仅当用户明确要求某项能力（如 1080P）且匿名路径不可得时，将能力缺口报告给用户。
- **宿主能力声明**：若当前环境无内置浏览器，先报告能力缺口再启用可用的已授权工具，不假设不同宿主具备一致的浏览器能力。

## 登录态判定顺序与状态枚举

按以下固定顺序判定内置浏览器状态：

1. 先在当前内置浏览器页面读取可观察登录信号（账号状态字段、头像、用户菜单），记录观察证据；
2. 再从该页面发起目标能力请求（站点正常授权 API 或页面 UI），记录实际返回；
3. 仅当页面明确显示未登录或页内请求明确返回登录门禁时，才判定需要用户登录；
4. 页面已登录但目标能力仍不可用时，记录当前账号/能力不可用并按技术限制回退，不要求用户重复登录；
5. 无法从页面确认登录态时，记录“尚未确认”，复查页面 UI 而不靠外部匿名结果下结论。

四种登录态枚举严格区分、互不混写：

| 状态 | 含义 | 允许动作 |
| --- | --- | --- |
| `anonymous_request` | 匿名或外部请求结果 | 仅作诊断或无浏览器降级；不作登录态依据 |
| `browser_logged_in_without_capability` | 页面已登录，当前账号无该画质/权限 | 记录原因并按已确认画质回退；不要求重登 |
| `browser_logged_out` | 内置浏览器页面或页内请求明确未登录 | **唯一**可触发请用户登录并等待确认的状态 |
| `browser_session_unverified` | 无法确认页面登录态，或宿主无内置浏览器 | 保持未确认；有浏览器时复查 UI，无浏览器时走降级路线 |

浏览器取帧脚本返回码的对应处理：

- `quality_unavailable_for_logged_in_user` → 不要求重登，按顺序尝试下一允许档位并记录原因；
- `login_required_for_quality` → 请用户在当前内置浏览器完成登录并确认，确认后重试同一档位；
- `browser_session_quality_unavailable_unverified`、`quality_request_failed`、`quality_not_honored` → 浏览器路径失败或未确认，先复查页面 UI 或重试，不据此宣布“需要登录”。

## 画质门禁

画质回退只能由已确认的技术限制触发：

- 请求 1080P 时，若内置浏览器确认未登录且平台要求登录，立即停图并请用户登录，确认后重试 1080P；不在登录未决时静默降级到 720P/480P/360P。
- 页面已登录但 1080P/高帧率不可用时，记录“当前账号无该能力”并回退至已确认的可用档位（软件演示最低 720P）。
- 登录态尚未确认时记录“尚未确认”，先复查页面再决定后续路径。

## 允许与禁止的探测方式

**正确做法**：通过当前绑定的内置浏览器页面检查 UI 与站点正常授权接口；无内置浏览器时使用公开元数据与匿名路径并标注 `anonymous_request`。

**硬性禁止**（不得绕过门禁或窃取会话）：

- 禁止用 `sqlite3` 读取浏览器 `Cookies`、解密 Cookie 或导出会话存储、密码与访问令牌；
- 禁止用另一个 Chrome 进程、`--user-data-dir` 副本或外部 HTTP 客户端加载同一 profile 后读取 `window.__INITIAL_STATE__.user.isLogin` 等字段判断登录态（profile 占用、Cookie 解密/分区隔离会误判为未登录）；
- 禁止凭匿名 `playurl`、匿名页面或低清接口未返回高画质而推断内置浏览器未登录；
- 禁止在登录态未确认时要求用户重新登录，或单凭隐藏控件中的“登录可享”文案判定未登录。
