# 逻辑与状态原型

本参考用于通过操作理解业务规则、状态转换或数据模型。需要同时判断视觉与操作时，结合 [UI.md](UI.md)；范围、验证和交接规则由 [SKILL.md](SKILL.md) 统一负责。

## 1. 明确可观察的问题

用用户的领域语言说明初始情境、可执行动作、需要理解的结果和仍待确定的行为。只纳入回答本次问题所需的状态及动作。已有规则和待讨论方案明确区分，演示某个结果不等于该结果已获批准。

*完成条件：用户知道演示在探索什么，哪些结果已有依据，哪些仍可调整。*

## 2. 分离规则与演示外壳

将状态转换或计算放入可独立理解的窄模块，页面通过其动作接口驱动它。依据实际问题选择 reducer、状态机、函数集或有状态模块，不为演示强造架构。业务规则不依赖页面内部结构，便于后续核验或评估复用；原型中的实现仍需经过正式实施要求的检查。

使用隔离、可重置的示例状态。持久化本身是问题时，使用明确标识的临时存储，并说明哪些持久化行为已真实验证、哪些只是模拟。

*完成条件：规则可以脱离演示布局解释，状态可恢复到已知起点。*

## 3. 让用户自由探索和按场景体验

提供两种可按问题组合的体验方式：

- **自由操作**：用户可尝试动作顺序和有关的非法操作，观察系统为何接受、拒绝或产生某种结果。
- **引导场景**：提供正常路径、重要边界及易误解的转换；每一步是实际可执行的操作，开始场景可重置到已知初始状态。

用可读字段、变化提示或适合当前问题的图示展示相关状态，避免只能查看代码或原始 JSON 才理解结果。领域标签描述业务意义，不以内部函数名代替说明。与实际 UI 组合时，额外的演示按钮和状态面板放在明确区分的工具区域；不必把它们塞进产品界面。

*完成条件：用户能按引导复现关键情境，也能自行尝试并看懂状态变化。*

## 4. 选择便于运行和分享的载体

纯逻辑演示适合单个自包含 HTML：内联必要内容，无需安装、构建或启动服务即可打开、分享和重访。若需体现真实项目中的交互或平台能力，选择现有框架中的隔离演示或项目入口；保持运行方式简单，并说明独立文件不能代表的部分。

演示外壳保持克制，重要视觉设计问题交由 UI 路径表达。用户要求调整动作或场景时，更新相应规则与展示，而不是扩展无关未来功能。

*完成条件：交付载体足以表达问题，接收者知道如何运行，不承担无关设置成本。*

## 5. 实际运行并交接结论

运行引导场景及相关自由操作，检查状态变化符合当前演示规则，并明确规则是否仍待用户判断。记录观察、用户确认的结论和仍未解决的问题；保存演示及其可运行起点。交付和正式实施交接按 [SKILL.md 第 5、6 节](SKILL.md#5-体验反馈与交付) 处理。

*完成条件：已验证演示能够表达本次问题，原型和结论可以恢复与复核。*
