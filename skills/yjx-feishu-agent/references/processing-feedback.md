# 原消息处理反馈

所有已授权群内、通过白名单及明确 @ 校验的请求，标记都加在本次用户消息上。引用的推送消息不变。

| 表情 ID | 含义 |
| --- | --- |
| `OnIt` | 已持久受理，可能排队或处理中，不表示 Codex 已开始执行 |
| `DONE` | Codex 已完成，且最终回复的飞书消息 ID 已落盘 |
| `CrossMark` | 需关注：请求受阻、失败、中断，或执行/回复结果尚未确认 |

先添加结果标记，再移除本功能创建的旧标记。标记在后台尽力更新，独立 HTTP 请求最多 3 秒，包含取令牌或分页的时间；它不延迟 Codex 或最终回复，也不保证固定展示时限。缺权限或网络异常可能导致缺失、旧标记残留或暂时并存，不能仅凭表情决定重发任务。

标记读写分别需要 `im:message.reactions:read` 和 `im:message.reactions:write_only`（或接口允许的替代权限），机器人须在群内。缺权限时保留原消息收发，记录不含密钥/消息正文的 `feedback-warning`；不自动扩权。普通表情操作参考已安装的 `lark-im`。

状态保存在仓库外 `feishu/<app hash>/feedback`，与 `messages` 任务日志分开。只管理本功能创建并记录的 reaction ID；其他人或预先存在的机器人表情不清理。添加回执未知时保留未知状态，仅通过只读查询核对；无法唯一归属时不重复添加。删除结果未知时不盲重试。

重启按本功能版本标识扫描任务记录，凭已落盘的 Codex 完成状态和最终回复 ID 恢复标记；证据不足转为需关注，不重新执行或发送回复。已完成回复后的来源登记失败仍可标记完成，路由故障需另查。升级前历史请求不补标。

处理异常时，尚未尝试最终回复才发送一次失败说明，发送意图先落盘；已经尝试回复但结果未知时不再发送说明。正常的受阻提示继续保留。Agent 无需额外发“收到/处理中”文字或手动维护这些表情。
