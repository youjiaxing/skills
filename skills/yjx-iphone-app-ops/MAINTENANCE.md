# 维护约定

修改本 skill 的职责、能力、实现或适配时先读本文。运行任务按 `SKILL.md` 路由。

## 职责边界

本 skill 根据给定目标和授权，建立并维护 iPhone 控制链路，观察并直接操作 App，验证目标是否达成，返回执行结果和必要证据。

负责控制环境自身的部署、配置、诊断、维护和恢复，包括设备连接、Appium、XCUITest、隧道、WDA，以及 WDA 自身的构建、签名和安装。账号、密码、设备信任等需要本人完成的步骤应明确交接；触发系统认证前说明对象、原因、动作和影响，其他可执行准备仍由 skill 组织完成。

负责 App 页面读取、导航、输入、点击、滚动、手势和任务授权的写入，以及等待、结果核验、视觉观察和取证。查询和测试是这项通用能力的使用场景。

业务 App 的源码构建、签名、打包、安装、发布，项目级业务规则、测试体系和发布流程的制定维护，以及内容的独立事实核验、研究和推荐，由调用方负责。WDA 是控制工具，不属于这里的业务 App。

跨会话上下文保存、业务进度持久化和整项任务预算属于调用方编排。本 skill 提供操作状态与恢复证据，保留设备锁和会话标记等控制链路状态；不新增业务任务账本，也不直接触发上下文保存 skill。

## 泛用性

通用能力根据目标 App、当前页面和调用方目标工作，不依赖简康记或其他固定 App。原生语义、可检查 DOM、本机 OCR 和模型视觉是可组合的观察路径；业务解析器留在专用适配中，按需加载。

视觉表现任务主动提供截图供模型判断，元素或 OCR 不能替代视觉判断；信息查询优先读取必要文字；混合任务组合使用。优化读取范围和重复观察，不能以节省 token 为由漏掉目标所需证据。

个人路径、设备、端口和已有 WDA 标识放在本机配置中；仓库保留参数化模板及通用默认。已有部署可发现和复用，其本机值不回写成通用默认。

## 能力闭环

完整链路是：控制环境部署维护 → 页面观察 → 授权操作 → 目标验证 → 证据交付。故障时诊断、恢复、重新核验；无法继续时给出最后完成阶段、阻塞原因、结果是否未知及具体接管动作。

健康检查分层报告。进程存在、HTTP 成功、安装完成或截图生成，只证明对应阶段；控制链路需实际设备命令和目标 App 状态证据。

调用 Agent 持有原始目标、授权对象和关键条件，CLI 参数不构成授权。发送、发布、付款、下单、删除等明确交办的动作可执行；“测试这个 App”不隐含这些授权。身份和作用不清时先观察消歧，授权或关键条件仍不明才补问，普通步骤不反复确认。

任务目标决定通过条件。输入需确认实际清空及完整输入；命令成功、缺失 value、占位文字不能代替输入证据。发送或付款等需相应记录、对象和金额等后置证据；只测试 UI 呈现时，结论限定于该条件。查询的 `factStatus=unverified` 不因操作验证通过而升级。

协议结果未知时，等待、断言、截图和 finally 清理均遵守在途命令保护。先完成既有恢复流程，再重新观察；写操作不自动重放，测试数据仅按清理授权删除或恢复。

环境变更先确认服务和配置归属、本轮独占及无未决请求；以设备锁串行化本工具操作。跨项目仍需唯一 owner 协调；命令锁或 `--exclusive` 参数不是外部租约证明。按具体服务身份维护，保留恢复配置，维护后核验。占用者不明时报告接管动作。

## 扩展和验证

主入口保留执行流程和分支路由，命令契约及 App 知识按需加载。新增能力需说明目标、可观察结果、失败与恢复语义、授权和兼容性，避免把某一 App 的解析规则提升为通用规则。

保留现有命令字段、查询产物和消费者兼容性；新增验证结果独立表达。维护文档记录原则，运行契约记录操作，不复制历史本机状态。实际验收范围及缺口写入 `references/roadmap.md`。

关键代码用功能测试覆盖协议、持久化、覆盖/删除、并发和重试；文档采用静态审查和链接校验。真实设备 PASS 需实际操作、可观察断言及本地证据。离线测试不证明真机通过；不创建模拟会话或 prompt 行为测试。
