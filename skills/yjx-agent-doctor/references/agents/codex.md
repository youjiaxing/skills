# Codex 适配

仅在诊断或预检 Codex 本地客户端、CLI 或其自定义模型接入时读取。字段是否存在、取值及优先级以实际运行版本为准；本文件不是可整份复制的配置。操作权限沿用skill入口的会话边界。

## 生效配置与运行环境

先确认本次目标是桌面应用捆绑CLI、PATH中的CLI，还是远端执行服务；它们可能有不同版本。读取实际可执行文件的 `--version`、相关子命令的 `--help`，只在必要时生成临时schema并清理。

本地配置通常位于 Codex 配置目录中的 `config.toml`；配置目录可能由 `CODEX_HOME` 指定，否则通常为 `~/.codex`。解析现有位置，不为了诊断重设全局目录。确认实际选择的 profile、provider、启动参数和管理配置，避免仅看文件中某行就认定它生效。

优先核对以下字段，按需读取白名单值，避免连同认证字段一起打印：

| 位置 | 检查内容 |
| --- | --- |
| `model`、`model_provider` | 配置的模型与provider，是否被本次启动覆盖 |
| `model_providers.<id>` | 实际选中的传输协议、端点与中转路径；保留凭证在原配置中 |
| `model_catalog_json` | 活动模型目录的真实位置，目标条目是否来自手工复制 |
| `[agents]` | 默认子模型与推理设置；显式派遣和自定义agent文件是否覆盖 |
| `[features]` 与启动参数 | multi_agent 等能力开关是否在生效进程启用；命令行 --enable 或 -c features.* 是否覆盖配置 |
| 模型目录条目 | 本次故障或预检涉及的工具/通信格式或能力字段；不批量“纠正”无证据的字段 |

本地模型目录的设置不能直接代表云端或其他主机。桌面应用中的旧聊天和已启动的子代理也不能代表新进程加载的配置。当前会话的工具集合可能随模型或回合变化；先核对实际声明，把模型调用未暴露的工具与连接器未授权、业务MCP故障分开。一次成功不能证明先前“未暴露”的机制已定位。

Multi-agent 需要同时满足模型/协议声明、运行时 feature 和会话动作注入。multi_agent_version、模型目录里的 root/subagent 协作提示以及 [agents] 默认子模型只能说明配置意图；它们不能证明当前会话已经暴露 spawn_agent。先记录 session_meta、turn_context、生效启动参数和 additional_tools，再判断动作是否存在。

新环境尚无失败记录时，先按[案例索引](../cases/index.md)定位待核查的工具模式和通信路径。字段与历史案例相同只说明值得核查，不能证明当前版本或服务组合不兼容；当前schema明确拒绝的配置则可作为静态问题证据。

## 工具参数格式

当错误类似 `tool exec invoked with incompatible payload`，先定位实际声明的工具及其输入契约：

- 某些版本的代码工具要求原始JavaScript；普通JSON工具接受具名参数对象。
- 将代码包装为 `{"input":"..."}`，只有在该工具schema明确支持时才正确。
- 核对模型原始输出、网关转换结果和运行时最终接收值。业务MCP尚未收到请求时，不把本地参数拒绝归因为业务授权失效。

模型目录中的 `tool_mode` 可能改变工具暴露方式。历史案例中，某个第三方模型在旧版运行时下以 `code_mode_only` 运行失败，改用普通JSON工具通道后恢复；当前版本复核时，同一模型在新进程下使用 `code_mode_only` 已能读取Notion。这不证明代码工具为GPT专有，也不证明所有第三方模型或版本都适用同一值。

先核对当前版本支持的表示方式，再决定删除字段、设置有效枚举还是使用其他通道。尤其区分缺省、JSON `null` 与字符串 `"null"`；在捆绑CLI `0.164.0-alpha.11.1` 的解析测试中，三者都被归一为未设置。记录实际改动，不把“取消代码模式”当成精确配置差异。

修改结构化模型目录时，按原文件做定点编辑并保留备份；解析后整体序列化会改变缩进、换行和转义，造成与目标字段无关的文件差异。恢复时先还原原格式，只重放已授权的字段变化，再核对行数、缩进、换行和逐行差异。

## 子代理编排动作未注入

遇到“当前只有空壳 multi_agent 命名空间”或模型声称找不到 spawn_agent 时，按以下顺序核对：

1. 记录根模型、默认/显式子模型、provider、捆绑CLI版本、multi_agent_version、feature配置和启动参数；不要只看模型名称或模型目录。
2. 从同一会话的工具声明或 additional_tools 中确认 spawn_agent、wait、close_agent 或当前版本的等价动作是否真实存在。tool_search、协作提示和 [agents] 默认值不能替代动作声明。
3. 对同一二进制、provider、模型和只读算术任务做单变量对照：增加 --enable multi_agent 或等价的 features.multi_agent=true，再观察工具清单及原生 spawn/wait 事件。若恢复，记录为运行时激活/工具注入问题；不要先修改模型目录或切换模型。
4. 修复后的验收必须收到子代理真实回传，并在需要时关闭已完成的子代理。一次普通 codex exec 或独立 CLI 请求只能证明模型请求可达，不能证明原会话拥有原生子代理能力。
5. feature、模型目录或启动参数通常在进程/会话创建时加载。修复后重启对应 app-server 或创建新会话；旧会话保留原工具集合，不能用旧会话验收新配置。

当前已验证的Codex组合见[Multi-agent编排动作未注入](../cases/codex-third-party.md#multi-agent编排动作未注入)。该案例证明自定义 provider 与 deepseek-flash 在 feature 启用后可以完成原生委派；它不构成其他版本、provider 或模型的兼容保证。

## 子代理任务不可读或纠正无效

先比对初始任务及后续消息在发送端与接收端的记录。`gAAAAA…` 一类不透明载荷只是线索；只有接收端确实无法读取正文、且与投递路径对应时，才能归为消息兼容问题。日志中的加密存储本身不等于模型看不懂消息。

当前执行者收到不可读任务时应停止猜测并报告。观察到其他接收者任务不可读时，报告投递失败；已有相应会话授权才中断该任务并确认状态，否则建议停止。恢复同样遵循会话授权，并先核实传递问题已解决，不通过失效通道反复要求纠正业务操作。

有些版本的模型目录支持 `multi_agent_version`。排查时确认：

- 初始任务由哪个模型发送，后续消息和恢复操作由谁发出。
- 该运行时如何结合模型条目、feature和会话历史选择通信版本；feature关闭不必然覆盖模型目录中的版本选择。
- 只改接收方是否影响发送端产出的消息格式；分别做单变量比较，而不是同时改双方后直接归因。
- 切换协议是否改变工具集合及参数。历史版本中观察过 `fork_turns="none"` 与 `fork_context=false`、`followup_task` 与 `send_input` 等差异；按实际schema选择等价操作，不盲目复制工具名。

在本文件配套的[真实事故复盘](../cases/codex-third-party.md)中，发送方采用v1解决了一组混合模型委派的不可读消息问题。这是已验证组合的兼容性绕行，不是“所有GPT向非GPT派任务都应降级”的通用结论。

## 模型目录复制与能力声明

模板中的自我身份、上下文上限、推理级别、图像能力、工具搜索及响应模式可能来自其他模型。复制痕迹用于定位疑点，不能单独证明故障原因。

故障诊断优先核查与失败信号相关的能力；预检则将声明与当前可确认的服务支持范围比较。例如超限、截断或声明已超过后端支持范围时调查上下文；不要因为消息不可读就同时改窗口、工具格式和响应传输模式。对于未找到schema或服务支持证据的字段，记录未知，不发明开关。

## 验收与生效

从工具事件或业务真实状态检查初始调用与必要的后续操作；模型自报完成不等于保存成功。代理回显类历史证据也要关联同一接收者，区分请求的模型、配置的默认模型与服务记录的实际模型。

应用前后分别保留配置差异；验证副本与正式配置解析后一致。模型目录通常在启动时加载，历史会话可能仍保留原协议或工具集合：使用真正重新加载配置的新进程或新聊天核实生效，不承诺当前聊天立即变化。

交付时写清需要用户重启或重新创建哪一层，以及旧异常子代理是否保持停止。若用户授权扩展至其他发送方，分别说明验证过的组合；保持未授权的其他模型、业务页面和安装目标不变。

## 维护时查证

字段发生变化、需要新的取值或本地帮助不足时，检查与运行版本对应的官方资料：

- [Configuration Reference](https://learn.chatgpt.com/docs/config-file/config-reference)
- [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)

这些资料可用于确认配置与继承规则，不代表其保证某个第三方模型或中转网关兼容。`tool_mode`、`multi_agent_version` 等内部模型元数据可能不在公开配置参考中；需要当前运行时schema、明确的校验结果或实际运行证据支持。
