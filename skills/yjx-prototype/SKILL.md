# yjx-prototype

用可体验的原型回答文字难以表达清楚的设计问题，并将确认的结果交给后续实施。视觉、交互和逻辑探索可以组合；原型代码可以临时实现，确认的产品表现仍须可追溯。

评审、修改或重新设计本 skill 前，先读 [MAINTENANCE.md](MAINTENANCE.md)。普通运行按下列步骤加载所需参考；本 skill 自包含，无需调用上游 `prototype`。

## 1. 明确问题与授权范围

从用户请求、已有共识及项目规则中确定本次要观察或选择的结果。任务明确包含原型、视觉方案比较、交互或状态演示时，可自动使用本 skill，无需用户说出名称；用户也可手动调用。仅判断原型可能有帮助、但已有任务未包含或授权原型工作时，先提出建议。

只向用户询问会改变目标、主要方案、成本接受或权限边界的未决问题；常规制作方式自主判断。原型制作授权覆盖本次原型，不自动授权正式实施、发布或真实业务写入。

*完成条件：本次问题、待确认结果、制作范围及允许的副作用已明确；重大未决前提保持可见。*

## 2. 选择形式与验证深度

已有项目先查看相关真实页面、导航、组件、设计约定和必要数据语义，再根据需求选择沿用、局部调整或整体重构。检查现状是为了理解衔接，不将旧 UI 当作重设计的强制限制。

- **视觉与交互**：比较结构、信息层级或操作组织，或预览选定方案的页面流程时，读 [UI.md](UI.md)。
- **逻辑与状态**：需要通过操作理解规则、状态转换或数据模型时，读 [LOGIC.md](LOGIC.md)。
- **组合问题**：两者会共同影响判断时，读取两份参考，在同一原型或相互连接的演示中表达，避免强迫用户先把问题划入互斥类别。

比较阶段，每个方案都提供足以评估的视觉效果和影响选择的关键交互；差异涉及跨页流程，就在比较阶段实现该流程。文字需求对齐不等于视觉与布局方向已选定：视觉与交互原型的首轮变体数量及单方案豁免条件按 [UI.md 第 2 节](UI.md#2-按实质分歧制作方案) 执行；选定方向后，再补齐本次需要确认的完整流程。

*完成条件：产物形态、需要比较的差异和当前阶段的交互覆盖能回答本次问题；简化部分不会遮蔽关键判断。*

## 3. 构建可体验的原型

实现所选路径，使用贴近实际情境、身份可辨识的示例。关键状态与变化用用户理解的语言表达；演示控制、场景切换和调试信息与预期产品界面明确区分，按问题选择呈现方式。保留自由探索和引导操作能力，不要求每次展示所有工具或产生所有类型的产物。

默认以隔离的模拟数据和状态承接操作。需要研究持久化时，使用明确标记、与真实业务隔离的临时存储；真实外部写入仍须符合已有明确授权。复用现有生产入口时，先确认原型不会误调用真实写操作。

原型应容易运行和重访：根据项目与平台提供可直接打开的产物，或已核实的一条启动命令及准确入口。隔离和标识原型，保持现有生产路径可用。避免为原型建设无关的生产基础设施。

*完成条件：用户能够进入原型、执行当前覆盖的操作并理解结果；模拟与真实副作用边界清楚。*

## 4. 运行与检查

实际启动或打开产物，按本次问题操作关键路径和相关边界，检查导航、状态变化及影响判断的视觉表现。UI 检查遵循项目工具路由和用户浏览器偏好；覆盖目标设备或视口，报告实际检查范围。逻辑演示实际运行引导场景并尝试相关自由操作。

验证深度服从任务与项目要求，不将上游“快速制作”解释为可以交付无法运行、粗糙到不能判断的原型，也不默认套用生产级完整测试。适用的项目检查照常执行；自动测试有明确价值或项目要求时按相应规则处理。无法执行的检查说明具体限制，不以文件生成成功替代体验证据。

*完成条件：原型实际可运行，当前问题所需检查已完成，结果和剩余限制可定位。*

## 5. 体验、反馈与交付

给出准确入口、运行方式和本轮希望用户观察的差异，允许选择一个方向或组合不同方案的优点。按反馈迭代；用户的局部选择只确认它实际覆盖的内容。

交付时简要说明已经确认、应由实施承接的设计决策，区分假数据、后台模拟、临时入口及场景控制等演示机制。如果仍有影响当前设计判断的关键场景未呈现，简要指出；没有则省略。无需固定大表，也不把本就模拟的后端未实现列作设计缺口。

*完成条件：用户能体验并判断本轮结果；确认、建议与未决内容可区分，后续实施边界清楚。*

## 6. 留存并交接

将确认范围内的页面结构、信息层级、入口、导航、操作和状态反馈及关键选择理由，记录到项目约定的权威产物；已有规格或 ticket 时保留其身份和原型指针。保留可重访的原型作为设计的一手证据，包括有比较价值的备选，不将演示代码混入生产路径。

按项目规则和授权选择独立分支、隔离目录或稳定可访问的产物。提交、修改 tracker 和清理各按其授权执行；仅清理本任务明确可丢弃的文件，保留他人工作。没有 Git 或 tracker 的任务也应有可访问的原型与结论，不强制引入这些工具。

正式实施承接已确认的产品表现，允许必要的平台、响应式和无障碍适配；实质改变确认结果时，说明原因并重新对齐。原型的模拟实现需按生产要求替换或评估后复用，不能以代码重写为由让产品效果无依据地大幅走样。若用户另有明确实施指令，带着原型与结论交给相应实施流程；否则在本次原型交付边界结束。

*完成条件：原型和结论可恢复，正式实施有明确依据，剩余问题与下一行动方已交代。*
