# yjx-grill

在为执行对齐方案前，先理解用户需要解决的问题。自主调查事实，把补救方案与期望结果对照，询问尚未解决的核心意图、重大取舍及项目保留决定；不以问了多少问题衡量完成。

维护本技能前读[维护说明](references/maintenance.md)。普通执行不加载维护和历史。

## 执行边界

这是用户调用的讨论流程。对齐期间不实施业务代码，不擅自修改项目治理文件；讨论中的局部同意不授予实施权限。用户指定结论载体时按[发现与取证中的载体规则](references/discovery.md#用户指定的结论载体)完成当前切片交付。

明确要求协作讨论时，即使没有剩余问题，也给出可调整的综合结论并允许反馈。完整结果获得同意可以结束讨论，不反复确认未变化的结果；确认一个方案不等于全部工作已定，也不等于执行授权。

## 呈现密度

解释、事实、进度、阻塞与结论首句直接回答，使用直白中文和标准术语。条目按实际主题分组，关键项在前，不截断实质相关内容；避免空分类、套话和内部台账术语。

建议、依据与操作选择分层展示：说明用段落、简短主题标题或项目符号；数字列表用于有顺序的步骤或真实选择。说明列表与最后的执行选项不能共用编号、混在同一列表，或以相同样式连排而无明确分隔。面向用户的标签与模板键使用用户语言。

讲解每个讨论项（包括无需用户决定的已定项和 Agent 拟做的事；纯知会除外）时，先用引用块交代理解该项所需的最小背景：涉及对象是什么、现状与问题、依据；再在引用块外写要做的事、理由与结论。用户不必回读旧回复也能看懂每一项在做什么；问题的背景规则见第 5 节。

主张只保留一个主要归宿，第二次出现应增加不同边界或可观察后果。来源、假设与批准状态靠准确措辞区分，不强制按来源标签组织正文，也不把它们写进生产代码注释。

不阻塞主线的旁支后置；纯知会用短陈述，独立的新问题仍须通过提问门禁。关键节点说明当前状态、真正的下一步和行动方，不要求每轮重报全部进展。报错时给具体位置、观察结果、已确认原因及最小解除动作；原因未知就明确未知。

协议、配置和数据结构讨论使用目标语言原生定义，保留真实名称、类型、编号和必要注释，不把多字段塞入窄表。名称来自实际承载模块和项目惯例，未定点明确标出；锁、状态和组件说明具体归属与作用范围。图示仅在替代文字、澄清流程或所有权时用，控制在八行以内。

## 1. 理解问题并测试前提

讨论或设计 Skill、AGENTS.md、CLAUDE.md 等供 Agent 执行的文档时，在分析职责、信息层次和执行步骤前，通过宿主技能发现机制加载 `writing-for-agents`；其写作规则从设计阶段参与，不等到落盘时才补读。

定位实际所属项目根，读取适用协作规则及该根的一份可选 `GRILL.md`；不分层合并、不跨项目寻找约定。非仓库任务使用已明确的工作目录，边界影响规则适用时先查明。文件缺失可继续；存在但不可读则说明缺口，不能默认放权。冲突只阻塞受影响范围。

识别用户保留、已委托和已有有效定论的事项。依据实际项目和当前要求判断参与程度，不按语言、前后端或“内部细节”标签推断。长期参与要求或可复用约定可在自然节点建议更新根 `GRILL.md`；缺失本身不触发提醒，用户暂不需要时不反复追问，文件修改另需授权。

从上游报告、方案或评审衔接时，先在 Agent 侧恢复真实目标、已确认决定与未决事项。材料不是用户已读或已接受的证明；按目标和依赖选当前议题，不沿材料目录机械讲解，也不让旁支替代主线。

用工具查清与当前判断有关的事实，不让用户代查可发现的信息。区分观察、解释、需求与 Agent 推断；上下文足够后先用真实领域概念简要重述理解，再比较方案，让用户有机会纠正影响目标的解释。

目标含糊、只有补救方案、需要复杂机制取证或判断依赖视觉/创作效果时，按[发现与取证](references/discovery.md)选择适用分支。已有充分依据时直接推进，不增加固定发现问卷。

## 2. 划定范围并安排工作

把独立结果拆成连贯切片，识别共享前置条件，再完成当前切片。开始讨论或范围实质变化时简短给出可纠正的范围总览，直接进入就绪事项，不另设范围批准关口；用户不必先列尽所有问题。

只有答案会改变当前选型或可行性的调查才作为阻塞，独立核查可并行或后置。事实、取证结果和上游决策未定时，依赖问题尚未就绪；即使两个问题都必要，只要答案会改变对方前提、选项或建议，就不同时提出。

新增工具/工作流的使用者与分发边界、冲突在途改动的去留、原型和样段的表现前提，以及新 Skill/工作流的最小行为样例，按[发现与取证](references/discovery.md)处理，不把未决前提包装成实施细节。

## 3. 按意图与后果设置问题门禁

每次提问先说明未解决的选择、为什么影响结果，以及现有需求、证据、约束或委托为何未能决定它。只接受以下理由：

- **核心意图缺口**：答案会改变目标、用途或用户负责的优先级；容易撤销也要问。
- **有后果的人类判断**：成本、保证、所有权、权限或整体策略尚待接受；只有一个可行方案也可能需要判断。
- **项目保留决定**：用户或项目保留参与，且无有效确认或委托覆盖；不能以局部、内部或可逆绕过。

常规机制与不影响目标的局部实现由 Agent 推导，不因存在多个实现就问。章节安放、同义合并和排版通常自行处理；上下游职责已定，不让下游重新执行上游判断。工具受限或未经证实的风险不是决策选项。

重要事实需要解释，不需要再让用户确认。未知影响先调查，无法取得必要证据时报告具体阻塞。只在有新证据、拒绝理由矛盾、已选方案失败或遗漏重大风险时重开旧选择；另一种偏好不构成理由。

提问和交付形式分别判断：低风险的核心意图澄清不自动要求正式方案，项目保留事项也不自动要求。需要有后果的人类判断时记录正式方案义务；答完问题、接受唯一方案或选择维持现状都不消除必要评审和批准。

## 4. 维护覆盖与来源

在首个问题前、每次回复或重大证据更新后、切片完成前，内部核对范围内所有建议、保留事项和重大选择：

- **来源**：用户明确要求、已核实事实、用户确认决定或 Agent 推断，分别保留证据位置。批准不会改变来源。
- **覆盖**：待取证、待用户、已解决或有依据地排除；记录前置依赖及处理理由。低风险默认也要通过提问门禁，不能替未确认的人类选择作主。

台账不必另建文件，也不直接展示给用户。保留备选、代价、假设、风险边界和实际确认范围；局部同意只关闭对应分支，不能把一次授权扩成永久放权。

检查所有权、真源、身份、状态转换、一致性/并发、对外契约、失败恢复、兼容迁移、权限及整体策略。尚无答案可保持待定，不把分配了问题或测试当成解决。新证据使旧结论失效时，相关依赖退回待定。

有后果的未知项不能隐藏在默认值中；没有人类选择时可通过取证或明确的验收/审查约束解决，不机械地为每个边界造问题。用户没指出遗漏不证明覆盖完整。

## 5. 处理就绪问题

每轮零到三个就绪且正交的问题，优先目标、真源、所有权和外部保证等枢纽。先按已核实事实、项目禁令及组件真实能力裁剪不成立的选项；不得推荐违反已知边界的做法。

有真实问题时，在至多一句简短衔接后先给 `Q<N>` 问题标题，下方用引用块重建本题必要背景，选项放在引用块外。背景不加“上下文”等标签，不把推荐方案当成既定前提。

问题须无需打开链接或回读旧回复即可理解：带上相关现状、有效约束、必要术语解释、真正未决点与答案影响。只补本题需要的背景，不复述整份报告；即使此前信息很短，也不假定用户已经读懂，不追问“是否看懂”来替代说明。

- **有真实替代方案**：从 `1` 编号，推荐项在前，说明理由、真实成本、适用条件和当前不选其他项的原因；允许自定义答案。
- **只有一种已知可行方案**：解释限制来源、后果及需要接受的条件，不虚构竞争方案，不用“是否同意”代替真实取舍。
- **意图尚待发现**：使用聚焦的开放问题，给足背景但不替用户诊断。

问题编号在当前连续上下文中递增，同一未决选择的澄清沿用原编号；压缩后丢失编号可从 `Q1` 重新开始，不为编号回溯历史。解释、进度、事实或既定选择不用问题编号。

收到回答后只更新它实际解决的范围，立即重算剩余就绪事项：同轮继续提出当前切片的新问题或进行必要取证，不只确认选择便等用户说“继续”。显示新变化和真实剩余边界，不复述全台账。

用户问澄清时只回答该点，等待其对原问题的回答；用户困惑时说清实际变化和剩余选择，不再套模板。新回答推翻旧前提时仅重开受影响部分。独立切片先按下一节收敛，再切换。

## 6. 收敛并交付每个切片

完成前核对：范围内建议、保留事项、触发条件、转换、权限、失败保证和重大成本均有依据；必要评审与批准已完成。没有就绪问题却仍有待定项，表示等待或阻塞，不是完成。

表现前提须先得到原型/样段确认或用户明确的其他处理决定，把结果合入方案后再评审和请求生产实施批准。已指定持久化载体的结论及修订同步写回后，才能切换切片；详见[发现与取证](references/discovery.md)。

按实际利害选择交付形式：

- **直接结论**：没有因重大人类判断产生正式批准义务。自然说明结果，不强造契约或重复批准。全部范围收敛、必要评审完成、当前可实施而缺明确执行指令，且用户并非只要规划时，在最后独立给出“按此方案开始实施（推荐）／仅保留结论，暂不实施”两个编号选项。
- **正式对齐方案**：已记录正式方案义务。起草、送审或请求批准前，完整读取[正式方案要求](references/contract.md)，形成经过评审的方案并取得明确批准。

围绕实际问题和最终行为综合结果，说明理由、已接受代价、边界、重大假设、真实未决点与下一步。没有的主题省略，不按问答编号重放历史；行为条件和结果优先，函数名/调用链仅作必要依据。

完成当前切片后继续检查其余范围；用户停止、暂停或缩小范围时保留未决和评审义务，不把剩余工作标成已完成。整体结束时区分对齐完成、可否实施及是否已有执行指令。

## 7. 按风险评审

正式方案在批准前必须评审；直接结论按实际风险和治理要求评审，不能因为评审就自动升级成正式方案。进入评审前读取[独立评审](references/review.md)，遵循上下文隔离、真实任务状态和发现闭环要求。

存在未解决的实质正确性发现，或不可替代的独立评审尚未完成时，报告具体阻塞，不能请求批准或宣称可交付。

## 8. 在交接中保留授权

讨论中的局部同意只解决相应选择，不启动实施。最终确认点区分批准结论、授权实施和指示开始；正式方案的三项选择按其专题执行，直接结论的执行意图选项按第 6 节执行，避免多索要一句“开始”。

单独保留真实实施授权及边界。允许实施但未要求开始，或明确只批准结论时，不开始；已有有效执行指令无需重复申请。未披露的默认值不从整体同意获得权限。

用户要求正式可用的交付、目标与边界已齐且已授权指示执行时，交给实施流程并完成验证，不能继续用澄清代替工作。只有新的核心意图、重大取舍或权限变化才回到讨论。

“继续”等简短回复按当前活动和实际意图解释，不用关键词白名单；继续讨论不自动变成实施，恢复中断执行可依赖仍有效的授权。活动不清楚时处理可推进的对齐事项，或只问真正缺失的执行意图。

已批准行为或边界重大变化须重新对齐、必要评审和批准；带条件批准按调整处理。先区分用户确认内容与 Agent 附带推断：后者与现有机制不一致时默认沿用已核实机制并说明，不单独开审批。

交接前核对实际执行指令覆盖当前方案，未决事项不阻塞该范围。旧方案指令不覆盖实质变化后的方案；已撤回、失效或不清楚时补齐指令。独立子集可先交接，但保留其他范围及其确认状态。

任何交接都携带项目参与约定、已选决定的实际范围、必要精确结构及仍须对齐的边界，不能交给执行者自行补定保留事项。调用方确认不自动改变本方案的交付形式或扩大权限。

### 从边界违规中恢复

发现遗漏决定或过早实施时，先说明实际改动中哪些已授权、哪些是 Agent 添加及哪些未决；暂停有效授权之外的继续修改。后续讨论可决定保留或修订，但不能追认过去已获授权；撤销也需授权，保留用户工作与依赖。
