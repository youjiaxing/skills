## 能力承接与本地取舍

| 上游能力或做法 | 本地处理及理由 |
| --- | --- |
| 问题决定原型形式，视觉与逻辑两条路径 | 保留两种能力，允许组合；用户的问题不总能被划为互斥类型。 |
| 多种结构差异布局、切换与组合优点 | 完整保留；探索时用于直观选择，收敛后可改为一条连贯流程，不机械固定三个或最多五个。 |
| 嵌入已有页面、新路由作为另一种载体 | 保留真实上下文的判断价值；先查现状，再按需求决定沿用、局部改造或整体重构，而非强制旧 UI。 |
| URL 定位、刷新稳定、浮动选择器、键盘操作 | 保留便捷比较和重访；按平台适配具体手段，演示控件与产品界面分离并限制在原型环境。 |
| 原型快速制作、跳过打磨 | 控制无关工程投入；用于判断的视觉与关键交互仍须认真呈现。不能用粗糙占位掩盖方案真实效果。 |
| 一次制作多个可比较方案 | 采用渐进覆盖：各方案实现影响判断的交互，选定后补齐本次确认范围；跨页差异在比较阶段就呈现。 |
| 自由操作、可重置引导场景、正常/边界/非法路径 | 保留；按问题选用，不要求每次都交付全部工具。 |
| 用领域语言展示完整相关状态 | 保留可理解性；状态面板可放入演示工具区，不强制污染产品界面。 |
| 逻辑模块与演示外壳分离、模块可评估复用 | 保留责任分离；复用仍需正式实施的检查，不把原型完成当作生产质量证明。 |
| 单文件 HTML、项目一条命令可运行 | 保留便捷运行与分享；纯逻辑优先独立演示，有宿主且需预览页面衔接时按实际项目提供入口。 |
| 默认无持久化、UI mutation 用 stub、必要时 scratch | 保留副作用隔离；涉及持久化研究时才使用隔离临时存储，真实外写按授权处理。 |
| 不写测试 | 改为与问题和项目要求相称的验证；实际运行和页面操作不可省略，也不默认套生产级完整套件。 |
| 原型留存为 primary source，记录选择与理由 | 保留；按项目规则与授权选择分支、隔离目录或稳定产物，不强制每个任务有 Git 或 tracker。 |
| 确认后折叠进真实代码 | 设计结论交给正式实施；确认原型不自动授予生产实施权限，正式表现不能因重写代码无依据地走样。 |

保真针对用户要判断的产品表现，不要求后台和基础设施与生产实现相同。假数据、场景控制和后台模拟应与确认的设计区分。确有影响设计判断的未呈现场景才披露，不以一般“后端尚未实现”凑缺口。

模型自动调用和手动调用并存。触发依据是任务已经要求或授权原型/方案比较/可操作演示，而非必须命中某组词；自动调用不扩大任务范围或授予真实外部副作用权限。
