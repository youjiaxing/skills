# 游览路线、地图与保存

## 安排与交付层级

默认 **主线＋可选点**：主线从容完成游玩、就餐、转场和休息；备选不算必须完成，不用它们填满行程。普通游玩用上午/午饭后等时间段；车票、预约、最晚入场/闭园等固定锚点保留精确时间。依赖具体班次时，先核目标日期实际存在的车次与时刻；在预售期内另核可购状态，未开售则说明预售期与预计依据，再据其倒推，不用假设班次。顺路不是唯一目标，先满足已定安排、开放窗口、天气与体力。

先保留用户看重的核心体验与时间窗口，再比较配套安排。新增时间、费用或体力约束时，与原有目标一起求解；如无法兼顾，说明具体要牺牲的内容，交由用户取舍，不自行将其删掉。交通、住宿和用餐的选择顺序由本轮目标及已定事项决定。

围绕游玩安排未定住宿时，先评估游玩与吃喝片区，再把入住、游览、用餐、必要的取行李及离开片区一起比较；已订住宿作为固定条件。主推理由应覆盖影响选择的实际接驳、体力和费用，不能只因某片区查到的资料更具体就改变优先级。

需要连续讨论的规划，按相互依赖的选择逐项推进：先查清当前选择的关键事实，给出可靠选项、推荐理由和取舍；只有用户的选择或缺失条件会改变下一步时再提问。用户选定后将其作为后续条件推进，无依赖的查询可先行，不把每个查询步骤都变成确认环节。

设计游览路线时，先核查片区内值得停留的内容，再安排通行。说明主要看点、停留与休息安排；适合弹性游览时提供可选延长或缩短段。轻松短线也应保留核心体验，地图算出的通行路径本身不能代替完整玩法。用户重视当地特色时，用具体场所、内容或店铺说明价值，不只以“热门”“集中”作为推荐理由。

按需求增加交付，不机械制作完整地图：

1. 简单查询：地点双平台入口。
2. 多去处比较：用普通高德网页展示相关候选，包含餐饮，帮助判断片区与顺路关系；地点密集或跨度大时，分为全城总览与片区放大，保持标注可读。
3. 形成行程并需要地图：位置总览＋分日/分段路线，区分主线、备选、餐饮与住宿；简单单日可合并路线。时间表里每处位置变更都要有对应的图；多点步行游览执行下述“高德步行＋途经点分段路线”，转场段用驾车/公交路线，单点停留给该点的位置图。各段交通方式、耗时与缓冲详见该节，不把直线距离当实际通行。

面向使用者的行程攻略按 [攻略交付结构](#攻略交付结构) 组织：住宿写进当天时间表的对应时段，位置总览作为路线层的一部分。

## 攻略交付结构

面向使用者的行程攻略，每天以一张当天时间表为骨架，正文按日期和当天时段顺序排列，不用“当前时段优先”之类的动态排序打乱结构：

1. **当天时间表。** 每天一张，按时间覆盖从出门到回程，不与其它日期混排；车次、预约、最晚入场、闭园等固定锚点精确到时刻。每条涉及位置变化的安排都写明交通方式与该段实测耗时（步行、打车、公交、接驳各自独立），按实际耗时加进出场、等车、找路和幼儿节奏留缓冲；耗时来自本次路线核查，未实测的段标为估计并说明依据，不留给使用者自行估算。
2. **当天要用的清单。** 景点内有演出、设施或乘坐项目时，挂一份可筛选的记录，逐项附开放时间、适用年龄或身高、注意事项，本次所选时段留在时间表；没有这类内容的日子省略。
3. **当天要用的路线。** 时间表里每处位置变更都要有对应的图：多点游览给按游览顺序分段的高德实际路线，跨点转场给驾车或公交路线，单点停留给该点的位置图；跨度大时按城市或片区拆图。只有整天不移动才省略。

骨架固定、条目按当天情况增删，单日行程同样如此，只省略当天没有的内容；未形成行程的简单查询不套用本节结构。地点详情在正文出现的位置就地给出影响当天行动的信息（开放时间、限制、预约要求），其余背景折叠；清单的注意事项按 [来源选择](sources.md#社区内容读取) 的证据约束填写。

**以计划为基准。** 攻略是一份大致照着走的计划，正文以计划为内容，已过日期保留原计划。用户顺口给出实际结果时，就地改写那一条；不另设“实际”栏，不要求逐日回填，也不做计划与实际的对账。不写关于文档自身的说明，例如“已过日期：保留原计划，不补写实际到访时间”这类交代文档处理方式的句子。

**同一事实只写一处。** 时刻与各段通行耗时归时间表，场次与限制归清单，走法与路线图归路线栏，不在对应结构下方复述结论。只对未来有效的条件句和待确认项，在对应时段过去后清除。

需要筛选或会随日期变化的内容用结构化记录承载（如 Notion 数据库：节目、项目、地点、候选酒店），时间表和路线放正文并引用条目，减少同一信息在多处重复。交付物只呈现结论与依据，不写入查询过程、候选淘汰推理或 Agent 的决策记录；这些留在会话或折叠的备选区。

交付或保存前通读一遍，检查：同一事实是否重复；是否有已过期的条件句或待确认项；是否有关于文档自身的元说明；是否有残留旧方案、失效链接或不适用于本次的通用内容。

## 工具分工

- **[普通高德网页版](https://www.amap.com/)**：默认用于向用户展示地点之间的位置关系、整体概览和实际路线。先确认当前页面能同时展示所需地点；只有起终点的路线图不能冒充全部候选总览。
- **[高德地图小程序网页版](https://wia.amap.com/)**：用于编辑和维护本次旅途的地点集合，突出本次相关点；搜索真实 POI，按地区/日期/用途分组并添加备注。管理界面不作为默认的概览展示。按需在此制作路线，官方支持[多选制作路线](https://lbs.amap.com/api/wia/tutorial/start/pc)及[顺路规划](https://developer.amap.com/api/wia/tutorial/route/plan_route)。
- **高德 App**：用户可打开上述地图小程序，查看本次旅途点位，并使用高德原生能力编排路线和导航。地点集合与已确定的游览顺序分开；只维护点位不代表用户已选定路线。实际交付链接的手机打开效果仍按本轮验证结果说明。
- **高德 MCP 专属地图**：若本次暴露相应工具，可生成 App 导入链接。手机打开、保存、分享分别验证，未实测的项目注明；这与网页持久地图是两种产物。
- **高德导航入口**：负责实际逐段通行。地图中多点游览顺序与道路算路区分说明；步行游览不能套用机动车绕行。餐饮、停车点和必要出入口纳入真实动线；地图标记公园中心不能代替所需入口。
- **Notion**：保存日程、说明、待办、预约与地图链接；不承担导航。户外轨迹工具只有明确地形/爬升需求且现有能力可用时再使用，历史轨迹不证明通行许可。

默认复用真实地图；确需额外网页时再制作，示意图标清比例和路径限制。需要手机查看或 Notion 嵌入时先核交付地址是否可访问；本地 HTML 生成成功不证明已公开托管或可嵌入。

需要在手机查看整张旅行地图时，取得地图自身真实的 App 分享入口，与电脑编辑/管理网址分别标注；单个地点链接不能替代整张地图。沿用已取得的有效分享链接，编辑后回读同一地图的内容；拿不到手机入口时，说明缺口并提供可用的地图码或已核打开路径，不猜跳转参数。手机实际打开效果仍按验证层级说明。

### 普通高德多点总览

优先使用[官方多点标注 URI](https://developer.amap.com/api/uri-api/guide/mobile-web/points)：`https://uri.amap.com/marker`，以 `markers` 参数传入点位，`callnative=0` 用于网页展示。官方文档核验于2026-10-20：支持PC和移动端，每个链接最多10点；每点可用真实 POI ID，或高德的“经度,纬度,名称”，点间以半角 `|` 分隔。用 `URLSearchParams` 编码参数；名称用简短、可区分的标签，避开作为分隔符的逗号和竖线。超过10点按片区或用途拆图。

打开后检查实际截图：所有目标点均可见、不被侧栏遮挡，边缘有余量；跨度大或标记密集时补片区放大图。每张图附对应图例，局部图可能重新编号，按实际显示核对。总览中的编号只标识地点，不代表已选定的路线顺序；区域代表点与具体入口分别说明。

### 高德步行与途经点分段路线

非室内、多地点步行游览采用“位置总览＋按游览顺序串联途经点的实际步行路线”。纯室内、单点查询或用户指定其他交付方式时按需调整。

1. **先定玩法，再分段。** 对照官方园图、开放公告与实走攻略，梳理沿途可看的内容、主线和支线，再确定起终点与途经顺序。按区域、日期或交通方式切段；缆车、小火车、公交等单独衔接，各步行段在实际上下客位置接续。餐饮、休息、必要出入口纳入安排，可选支线与主线分别表达。
2. **核对真实地点。** 从具体地点详情取得名称、POI ID及同一地点的高德坐标，优先实际入口、车站或乘车口。附近餐厅、商店或场馆中心仅能明确标为片区参考；入口未知时保留缺口，不把相似名称或邻近点冒充入口。
3. **用步行模式添加途经点。** 在普通高德网页选择“步行”，按计划顺序添加途经景点；当前页面支持时，可用下述链接参数载入。按已定游览顺序核对结果，不把起终点算路或自动推荐顺序当成完整游览路线。途经点较多、文字拥挤或混入不同交通方式时拆图。
4. **检查实际线路。** 打开路线并核对步行模式、起终点、全部途经点及顺序，读取距离与预计耗时；对照官方园图、封闭范围、单行线与实际通道检查绕行。高德算出路线不证明园内实时通行。线路落入封闭区、错误入口或不可走区域时，修正定位、拆段或改走已核通道，再重新检查；仍无法核实时明确缺口，不交付为可直接照走的路线。园内设施之间算路常沿园区外道路绕行，距离明显长于园内实际步行时按官方园图改为园内接驳或已核通道，或只把该图标注为接驳参考，不写成园内步行路线。
5. **交付与时间表对应。** 每段写清“起点 → 途经点 → 终点”、主线／支线、交通方式、高德链接和截图。截图须能辨认全部途经点及线路，必要时分段放大。纯步行距离、耗时与看动物／参观、排队、用餐、休息、进出场及交通等待分别计入预算；个人时间表按同一顺序衔接，地图编号不代替时间安排。
6. **保存当前版本。** 按任务授权将每段路线链接、截图及必要官方园图保存到指定攻略；回读核对图、链接、时间表与途经顺序一致。路线变更时同步替换正文入口，旧图如保留须折叠标明不适用。现场调整从用户当前进度接续，已走过的点不要求重新走一遍。网页可打开与手机App实际唤起分别验证。

#### 网页路线入口参数

普通高德网页的 `https://www.amap.com/ssr/dir` 可载入步行及多途经点。以下是已实际使用的网页入口形式，不是稳定的官方开放API契约；页面行为变化时回到可见的步行规划界面操作。

| 参数 | 用途 |
| --- | --- |
| `type=2` | 步行模式，打开后仍核对当前模式。 |
| `fname`、`flon`、`flat`、`fid` | 起点名称、高德经度、纬度、真实POI ID。 |
| `dname`、`dlon`、`dlat`、`did` | 终点的对应字段。 |
| `vname`、`vlon`、`vlat`、`vid` | 途经点的对应字段；各字段内部按同一顺序用半角 `\|` 分隔，数量一致。 |
| `type=0` | 驾车模式，用于打车或自驾转场；同一条链接仍要在页面上核对当前模式与路线。 |

只给 `fname`／`fid` 与 `dname`／`did`、不带坐标时，页面会自动补全 `flon`／`flat`／`dlon`／`dlat` 并算路，可用这一行为取得起终点坐标；**途经点必须显式给出 `vlon`／`vlat`，只传 `vid` 不会生效**，缺坐标时会算成不含途经点的起终点路线。坐标一律从页面实际回填结果读取，不自行估算或从别处抄近似值。

**取得 POI ID：** 普通高德网页的搜索结果卡片图片地址含该点 ID，点开详情后地址里的 `id=` 参数是权威来源。同名地点先核对完整名称与地址再采用，避免用相近名称、邻近点或点评 ID 顶替。搜索可能把子地点归到所属景区（例如园内设施只返回景区主条目），解析出的名称与目标不一致时换入口重新取得，不沿用被改写的名称和坐标。

用 `URLSearchParams` 编码查询参数，保留实际已核的名称、坐标和ID。生成URL只代表构造完成；页面须实际展示所需途经点及算路结果，才能交付为已核路线。普通多点标注URI仍用于位置总览，不能代替这条步行路线。

## 高德账号收藏

用户要求收藏地点时，可通过已登录的普通高德网页版操作账号收藏；它与旅行地图小程序加点是两种保存方式，收藏不代表加入旅行地图或选定行程。按用户指定地点和范围执行，不把普通推荐自动全部收藏。

1. 优先连接内置浏览器，打开已核实 POI 的地点详情，核对名称、分店和地址。工具未列出某浏览器不等于应用不可用；用户提供当前页面时，尝试按该页面 URL 或标签引用连接。连接失败与高德未登录分别判断，限制结论限定到实际检查的入口和会话；浏览器类型按主文件的工具选择规则确认。
2. 检查现有收藏状态；已经收藏则保留，避免再次点击取消。未收藏时点击详情页的“收藏”，读取“已收藏”等明确反馈，并检查星标状态；若出现登录或验证，按主文件的访问限制规则处理。
3. 刷新或重新打开同一 POI，确认收藏状态仍保留，保存结果截图；批量任务逐个核验，分别报告成功与未完成项。网页收藏与手机同步分别验证，未在手机检查时，不声称 App 已同步，也不假定已归入指定收藏夹。

2026-10-21 已在内置浏览器实测：地点详情点击收藏后提示“已收藏”，刷新后金色星标保留；本次未验证手机同步、指定收藏夹或批量收藏，不将单点成功推广为这些能力已验证。

## 按任务保存

普通查询直接回答。用户明确要求保存/更新时，维护本任务指定地图/页面，同任务内不逐条重新询问；地点/路线放地图，日程说明放 Notion，按需选择，不强制双写。选择方案不自动授权保存；保存也不授权报名、预订、付款或公开分享。

写入前读取现状；保留已订安排、已购事项及相邻未改内容。换酒店等变化同步摘要、正文、相关接驳及旧名称引用；候选与已选/已付款区分。优先已有 Notion 工具局部更新。

行程资料面向实际使用：把新结论整合到已有日期或路段，避免不断追加重复总览和更新记录。正文突出当前安排、关键时间、必要限制与行动入口；地点背景、查询过程、证据和旧方案按需折叠或归档。详略与展开方式服从用户的用途和偏好，不强制所有地点折叠，也不把影响当天行动的信息藏入详情。

保存完成的依据：地图保存后刷新，点位、分组、顺序与备注仍在；Notion 更新后回读，指定内容正确且地图链接与站点顺序一致，相邻内容保留。打开页面或更新请求成功不单独证明保存完成。

部分写入失败时报告已完成和未完成，保留可用结果；不说全部完成，不为补偿失败擅自覆盖旧稿。仅记录当次指定资料，不默认建立长期生活档案。
