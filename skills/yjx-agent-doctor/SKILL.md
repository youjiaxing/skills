# Agent Doctor

当用户请求 Agent 故障诊断或新环境预检时，可自动调用，也支持用户手动调用。默认先诊断并给出修复建议；是否继续修复依具体会话要求和已有授权，明确要求修复时不额外设置重复确认。调用本 skill 本身不自动授权修改生效配置或操作其他运行任务。

面向 Agent 自身的配置、运行和服务接入问题，首版重点是第三方模型、兼容 API 与中转网关。业务应用自身的逻辑缺陷交回相应开发流程。

## 1. 确定目标与实际环境

沿用会话中的目标和范围，选择入口：

| 入口 | 起点 | 要得到的结果 |
| --- | --- | --- |
| 故障诊断 | 一条实际失败或偏离要求的操作 | 定位失败边界、原因和可行修复 |
| 新环境预检 | 尚未报错的安装、接入或配置 | 检查已知问题是否适用，区分可修复问题与待验证风险 |

识别本次涉及的 Agent、实际运行版本、模型与服务路径，以及生效配置的来源：全局、项目、profile、启动参数、模型目录、会话历史或远端管理配置。围绕目标取证，避免将一个接入问题扩成无边界的全机扫描。

模型接入的链路通常为：

`调用方 → Agent 运行时 → provider / 中转网关 → 模型后端`

涉及子代理时，再分别标出发送方和接收方使用的模型、运行时及通信协议。客户端的模型别名、配置的模型、请求中的模型和服务实际执行的模型可能不同；只将有独立记录的层级写为已确认。

能力声明、运行时开关和实际工具注入是三个独立边界。模型目录中的能力字段、multi_agent_version、协作提示或 [agents] 默认模型不等于当前进程已经启用对应动作；同时核对生效 feature、启动参数、会话实际工具声明和真实调用结果。

故障诊断保留用户原目标、偏离步骤和调用ID或时间，区分初始故障与恢复后的新故障。预检不要求先触发事故；从当前配置、版本支持范围和已有真实运行记录检查问题。

只输出定位问题所需的白名单字段和脱敏片段；避免整份打印配置、环境变量、请求头或会话。错误正文、URL查询参数和普通字段内也可能含凭证。公开案例去掉账号、私人业务内容和本机绝对路径。

按需加载证据：

- Codex 场景读取 [Codex 适配](references/agents/codex.md)。其他 Agent 使用该版本的本地帮助、schema 和官方文档，不套用 Codex 字段或宣称已有专属适配。
- 预检时读取[案例索引](references/cases/index.md)，只展开与当前 Agent、服务路径和配置相关的案例；故障诊断按症状查索引。没有匹配案例时继续通用调查，不为凑命中读取所有案例。

完成条件：目标、当前环境及证据缺口可定位；故障诊断能指出具体失败操作，预检能说明实际检查范围。

## 2. 诊断问题或核实预检风险

根据证据选择相关分支，不逐项修改所有可疑设置。

| 分支 | 优先核对 | 有区分力的证据 |
| --- | --- | --- |
| 工具调用 | 工具是否在当前会话暴露给该模型，工具实际声明的名称、参数schema、JSON或原始代码格式、并行调用与结果关联 | 会话实际工具集合、模型输出、运行时接收的载荷、校验错误；请求是否尚未到达业务服务 |
| 代理编排 | 根代理是否拿到 spawn、wait、close 或等价动作；feature、启动参数、根/子模型和上下文隔离是否一致 | 会话工具清单、编排动作事件及子代理真实回传；仅有协作提示或模型目录字段不算动作已启用 |
| 代理通信 | 初始任务、后续纠正、恢复消息和结果回传各自的编码及投递路径 | 发送端输出与接收端实际可读内容；版本由发送端、接收端还是历史决定 |
| 能力声明 | 上下文、推理级别、图像、工具搜索、流式响应等声明是否匹配真实接口 | 服务支持范围、请求拒绝或截断证据，而非另一模型的模板 |
| 网关与传输 | 请求/响应转换、角色与内容块、工具调用ID、认证和路由 | 转换前后的最小脱敏片段；HTTP状态与协议错误，不凭“兼容API”名称推断完整兼容 |

区分“模型没有生成正确格式”“网关改变了格式”“运行时不能解释格式”；无法看见某个边界时保留这一不确定性。调用在本地被拒绝，就不要先修业务应用的登录或权限。模型品牌或模板复制本身都不能证明根因。

先区分业务 MCP 不可用、连接器未授权，与当前模型/会话没有拿到工具声明。模型中途切换后继续旧聊天、模型调用未暴露的工具，都可能被描述成“MCP 不可用”；核对当前会话实际暴露的工具，并用真实 MCP 调用结果确认业务路径。

子代理问题先按边界分类：编排动作未注入、创建成功但任务不可读、动作载荷被运行时拒绝，或子代理已经执行但业务结果失败。不能用另起一个普通 CLI 进程证明原会话拥有原生子代理能力；也不能因为模型目录含有协作提示就跳过真实 spawn、wait 和结果回传核验。

匹配历史案例后，核对当前 Agent/运行时、版本、服务路径、字段语义与必要前提，再给结论：

- **已确认问题**：当前环境的schema、支持范围或真实运行证据已证明失配，可以提出针对性修复。静态证据足够时，不必先造成业务失败。
- **待验证风险**：配置相似但适用条件或兼容性未证实，说明缺少什么证据，不能直接套用历史修复。
- **当前不适用**：案例必要条件不成立，说明排除依据，不据此宣称整个环境无问题。

当前执行者发现自己的任务不可读时，停止猜测执行并通过可信通道报告。发现其他任务异常时，先报告状态；主动中断、恢复或重放按下一节的会话授权处理。保留中断与再次启动的时间，避免把主动恢复误判为中断失效。

完成条件：确认的问题与未证实风险分开，每个保留假设都能说明有区分力的证据或验证方法。

## 3. 给出建议，按会话要求修复

默认交付原因或风险、支持证据、建议改动、影响及仍需验证的部分。仅要求诊断或预检时，不自行修改生效配置、主动中断/恢复其他任务，或重放有副作用的调用。

已有明确修复、提前修复或相关验证指令时，在现有授权范围内继续；范围或实际影响发生实质变化时再对齐。真实调用的访问、费用和副作用也沿用该边界，缺少安全可执行路径时说明限制。

优先复用实际失败请求、已有日志及成功对照，验证同一契约边界。能在隔离环境安全重放真实调用时，保留原有输入及可判定的失败信号；否则使用只读证据说明结论和未验证部分。

每次只改变一个有依据的变量，例如工具格式、发送方通信版本或网关转换规则。明确区分“配置被客户端接受”“调用完成”“原故障消失”；进程退出正常或代理自报成功不足以证明后两者。

工具或代理编排未暴露时，先做同一运行时、provider、模型和只读任务的单变量对照：只切换 feature 或启动开关，再比较实际工具声明和原生 spawn/wait 事件。若启用开关后编排链路恢复，根因属于运行时激活或注入边界；这时不要把失败归因于模型，也不要改模型目录作为替代修复。对照必须使用真实的 spawn、wait、结果回传和必要的 close，普通独立进程只能作为模型请求对照。

涉及配置修改时：

1. 用当前运行时的解析或校验确认候选值和语义。缺省、JSON `null`、字符串 `"null"` 和禁用开关分别处理；同一字面值在不同版本可能解析成不同状态，不能凭历史案例互换。
2. 保留原文件和差异，限定目标条目及恢复方式。结构化配置文件只改目标字段，避免解析后整体序列化重写；若已发生重写，先按备份恢复原格式，再重放目标字段。单模型问题先修单模型；用户选择扩大范围时列出受影响发送方/接收方，并分别验证。
3. 用实际工具或服务结果确认输入、接收者、响应和最终状态；代理通信还要核对后续消息是否投递到同一个接收者。请求中的模型字段不能独立证明服务实际执行的模型。多条配置分别验收，一条通过不能代替另一条；服务端临时错误记为未验证。
4. 检查必要的相邻路径，例如默认子模型是否受通信版本变化影响。只有新失败或尚未解决的具体风险才扩大验证。
5. 比较修改后的语义差异，确认授权范围及其他字段。区分临时副本与正式生效配置；若需重启、新会话或远端重新部署，明确生效条件。

完成条件：诊断任务有可评估的建议；实施修复时，原故障或预检确认的问题有对应验证，修复范围、回滚和生效方式可定位。风险仍未验证就如实保留，不写成“已修复”。

## 4. 交付与扩展

先报告已确认问题、待验证风险或检查范围内未发现适用问题，再说明证据和建议。只有实际修改时才列修改位置、备份/回滚、验证及生效要求，并分开说明有意的配置差异与意外的格式变化。区分根因修复、兼容性绕行和临时隔离；结论只覆盖实际观察的组合与范围。

用户要求新增 Agent 适配、沉淀案例或维护本 skill 时，读取[扩展与维护](references/maintenance.md)。正常诊断不自动修改或发布 skill 仓库；入口保留通用流程，平台和案例细节按需读取。
