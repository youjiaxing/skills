# 知识筛选与沉淀

在已覆盖会话中发现知识候选，或需要复用、核验及修订已有知识时加载本参考。知识筛选独立于过程改进；无报错、无纠正或无整改建议的区段同样需要检查。

## 判断是否值得留下

围绕未来会用到的判断或动作寻找候选：解释机制的原理、已验证的有效方法、成功或零收益实验的适用边界、选型与排除理由、用户正向认可、实际能力与限制。同时检查“原先预期什么、实际观察到什么、差异会改变未来哪项判断”，保留意外发现与做对事情的依据。

需要核实认识时，定点读取本任务相关的代码差异、提交理由或验证产物；先确认与任务的关联，不以最近若干提交代替任务范围。产物说明实际变化，不能单凭它推定用户已确认某项决定。对每项说明：

- **认识**：得到了什么可复用认识，或需要保留的项目事实/案例。
- **证据**：稳定原文定位、实际工具结果或产物；分别标明用户确认、工具实测、助手推断。助手说“可行”不等于能力实测。
- **条件与限制**：适用对象、环境/版本、样本与未验证范围；结论强度不超过证据。依赖可变条件时，按下文补具体重验信号。
- **未来用途**：什么条件下读取它，能帮助哪项判断或避免什么重复探索。

方法按需保留前提、最小有效步骤和实际验证方式；决定保留备选及排除理由。只保留未来复用需要的细节，不强制给每项填同一模板或数值置信分数。

一次可靠核验即可支持有边界的知识，不要求跨会话重复；一次用户认可只保存具体案例，不能直接升级成长期偏好。成功运行仅支持实际观察到的能力，不能扩为所有环境都可用；认可某种方案不授予永久调用权限。没有新认识、没有未来用途或无法核实的断言不作确定知识沉淀；仍有价值的假设可在建议中标为待核实。

## 先查真源再提落点

从已知项目入口、当前任务产物及实际使用的 Skill 定点查找，不为知识候选遍历所有仓库或新建知识体系。逐项判定：

| 当前状态 | 处理 |
| --- | --- |
| 已有正文与边界，且可发现 | 复用已有位置，不重复写正文 |
| 结论相同，但新增证据有复用价值 | 在原位置补必要证据，不另建重复条目 |
| 正文充分，但相关入口难发现 | 建议在实际触发点补有读取条件的指针 |
| 正文或适用边界缺失 | 在已有真源补最小增量，保留依据 |
| 同主题，但适用对象或条件不同 | 保留有边界的变体，不把条件抹平合并 |
| 新旧结论真正冲突 | 对照双方证据，按下文查明冲突性质再建议修订 |
| 来源缺失或本次无法核验 | 标明缺口，保留既有证据；无法核验不等于结论错误 |
| 尚未确认所属体系或没有合适载体 | 交付候选与落点问题；不擅自新建知识库 |

冲突处理区分三种情况：描述落后于实际机制时更新描述；实现违反仍有效的规范时报告可能的实现问题；新的有效决定取代旧决定时确认授权、适用范围与生效依据。当前代码不能自动推翻规范，文件较新、重复更多或用户沉默也不证明更正确。未核清时列出双方依据并标待核实；充分依据支持替代后，保留必要的旧理由、证据与后继指针。

通用方法优先归已有 Skill，项目事实和决定归项目文档，单次选择/认可归已有专题案例。只有确需改变执行规则时才进入过程改进筛选，不能把全部知识改写成常驻提示词。涉及公开 Skill 时剥离私有身份、渠道、价格、密钥和项目细节，必要时只在私有真源保存。

## 复用与重新核验

在相关知识被复用或修订，且存在变化线索或证据缺口时，按变化原因重查；本次已有充分核验依据的内容直接复用。不把每次复盘扩大为全库审计。

| 变化原因 | 核验依据 |
| --- | --- |
| 事实或环境改变 | 当前权威来源、实际环境及其适用范围 |
| 用户或项目决定改变 | 适用、已授权且已生效的替代决定；其他项目的选择不能代替 |
| 工具、模型、API、依赖或配置改变 | 相关版本、配置和代表性行为的实际证据 |

对依赖临时条件的知识，按需说明具体重验信号、权威查询入口或检查方式，例如上游缺陷修复、版本/配置改变。升级只是重验信号，不直接证明结论失效或绕行方案可以移除；年久和未再次使用也不是删除依据。不设统一过期时间或后台重验任务。

分别说明事件当时是否解决、结论当前是否核实、相关规则是否已更新；三者不能互相代替。原始观察与本次重验结果分别保留实际日期、版本或环境，当前结果不能回填成当时已知。来源不可用或相互矛盾时保留旧证据及成功验证日期，注明本次尝试、缺口与下一核验入口；核验失败或仅尝试检查不能刷新成功验证日期，也不在受阻时擅自移除原有护栏。

默认使用只读证据；需要付费、对外写入或有副作用的实验时，说明必要动作并按本次实际授权执行，未获覆盖时只提出核验建议。

## 修订传播与后续使用

结论被收窄或替代后，沿已知来源、目标路径和直接引用，定点查找受影响的 Skill、项目文档及操作入口。仅查已确认所属体系，不遍历所有项目、不另建引用数据库。列出已核对位置、具体拟改内容及无法定位的缺口；真源已改不代表其他使用位置已同步。受影响目标超出授权时只报告待改位置，不能把本次复盘当成修改所有下游文件的许可。

具体化未来用途：“哪个现有入口，在什么条件下读取，影响哪项判断？”核查实际可访问的入口与引用路径，未知保持未知。入口支持发现时直接复用，缺指针时建议准确落点；实际接入归对应规划、排障或其他使用流程，不扩大本 Skill 的后台扫描、全局加载或其他 Skill 的自动调用资格。

指针存在只证明有发现入口；实际读取、采用及验证有效分别需要相应证据。核查不足时如实说明，不能把保存完成写成已使用有效。

## 交付与授权

仅报告有实际增量的知识、修订或发现性改进，说明认识及来源、条件、适用时的重验信号、真源拟增量和受影响位置；保存充分的条目内部复用即可。默认只建议，已获本次写入授权才落盘并核验链接、正文与边界。

落盘前重读目标文件，避免覆盖并行改动；遇到冲突时暂停受影响文件的写入并报告，保留其他已完成改动。跨文件修改不宣称原子完成，部分失败时按实际结果区分已改、待改及授权外剩余项，交付可审查的差异。

`retro-ledger` 保持改进候选/决策职责；知识正文不进台账，同源已拒绝建议仍按主 Skill 的新反证或用户要求重审条件处理，不能改名后重新推销。
