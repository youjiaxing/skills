# yjx-retro-skill

由用户手动触发。主会话主持复盘，从本次实际损失寻找值得修改的 skill 问题，而不是对指令逐条挑错。默认只调查并提出建议；修改、安装、提交 skill 或操作外部系统属于另行授权的实施。

## 1. 确定证据范围与分工

默认复盘当前会话中已完成的实质任务，截止本次复盘调用前；用户指定其他会话或任务时按指定范围。区分多个任务及其依赖，避免将复盘过程本身混入被复盘任务。

主代理负责理解用户意图、安排调查、综合归因和交付建议。按被复盘任务的原始对话是否仍保留在当前上下文中分流：

- **当前上下文完整覆盖被复盘任务（未被压缩摘要替换）：** 直接将当前上下文中的用户消息、加载的 skill、工具调用与输出作为主要证据，配合对目标 skill 文件、任务产物或 Git 状态的必要只读核验。全程由主代理单代理完成取证、归因、筛选与交付前核查；**不读取 [会话记录取证](references/session-evidence.md)，不查找或读取当前会话的磁盘原始记录（如 session JSONL），不启用取证子代理或独立评审子代理**。即使更早的无关任务曾被压缩，只要被复盘任务本身的原始对话仍在当前上下文中，仍走本分支。不把缺少宿主显式“未压缩”标记当作状态未知；若当前上下文中个别工具输出被截断或局部证据不足，直接记为证据缺口并限制结论范围，不借此回查磁盘会话日志或开启子代理。
- **被复盘任务在当前上下文中已被压缩摘要替换（含复盘前已替换或复盘期间被压缩），或用户指定复盘其他会话：** 当前上下文中仍保留的原始消息与工具结果可直接作为证据；对已被压缩摘要替换的区段或外部目标会话，读取 [会话记录取证](references/session-evidence.md) 定位磁盘原始会话记录并固定截止点，压缩摘要仅用于定位线索。将需要补读磁盘原始会话记录的只读工作交给上下文隔离（`fork_turns: "none"` 或平台等价机制）的子代理，传入本 skill、目标记录定位、用户目标与约束、明确的调查范围及返回要求；子代理分段读取并仅返回带定位的精简证据包，主代理按定位回查关键原文，不把整份日志载入主上下文。若宿主无法使用子代理，主代理说明限制并自行分段读取必要区段。

按本次目标建立轻量时间线与覆盖记录：用户要求和更正、实际加载的 skill、关键工具结果、失败和返工、最终交付及其核验。当前上下文分支直接使用上下文中的消息顺序、工具调用或事件定位；磁盘取证分支使用记录路径与行号或稳定消息 ID。记录已覆盖区段与缺失、截断、仅有摘要的区段。按时间线覆盖任务，再围绕疑点检索；仅搜索错误关键词不能证明已检查整个任务。

完成条件：能定位被复盘任务、实际使用的 skill 和证据范围；无法还原的部分明确标为缺口。未实际使用的 skill 不进入本次优化对象。

## 2. 从实质问题取证并归因

从错误、误解、返工、不必要操作成本和影响使用的交付缺口寻找候选问题。必要时按疑点只读核验相关产物、原始来源、脚本或外部实际状态，不完整重做任务。读取外部状态仍需现有访问权限；核验不能附带写入或重新执行日志中的动作。

对每个候选问题核实：发生了什么、偏离哪项用户目标、造成什么实际影响、当时适用的 skill 指令是什么。尽可能核实执行时版本；当前文件和事后 Git 修改不能直接代表当时版本。明确区分以下原因，可记录共同原因：

| 原因 | 处理 |
| --- | --- |
| skill 缺口、冲突、过严或缺少适用条件 | 检查最小修改能否改善同类任务 |
| agent 未遵守已有明确规则 | 记录执行偏差；只有证据显示规则难以发现、冲突或无法落实时才进一步建议修改 skill |
| 工具、环境或访问限制 | 指出能力边界；仅在 skill 的能力判断或降级流程有问题时建议修改它 |
| 本次任务特例 | 保持本次约束局部化，避免写成所有任务的通用要求 |
| 原因未知或证据不足 | 列明缺失证据及其对判断的影响，不当作已确认缺陷 |

对照已有保护措施和反证，检查问题是否已在后续版本修复。保留有价值的实际经验，但已解决的问题不再重复建议修改。Git 可辅助定位演进，不能单独证明会话因果或优化效果。

## 3. 筛选最小优化

只有同时具备具体证据、实质影响、可解释的 skill 归因，以及合理的未来收益，才进入优化建议。一次严重问题即可成立，不要求反复发生；重复出现也不能代替影响和归因证据。

优先选择解决机制的最小改动：澄清适用条件、调整导航、消除冲突、删减或放宽约束，或为机械步骤补充确定性工具。比较它带来的执行成本、上下文负担、维护成本和对其他场景的影响。措辞偏好、目录整齐或没有实际损失的流程差异，不足以支持修改。

预期收益是推断，不能表述为已验证效果。缺失证据会改变归因或修改方向时，保留为待核实线索；不要凭不确定性增加通用规则。

## 4. 核查与交付

交付前，主代理核查每项候选的证据、归因、预期收益及修改影响，解决有证据的反驳与遗漏。当前上下文完整分支由主代理直接完成核查，不启用独立评审子代理；仅在“被复盘任务已压缩或复盘其他会话”分支下，当主代理认为有必要或当前项目治理要求独立评审时，才按第 1 节的委派方式交给未参与取证或形成建议的评审子代理。

委派独立评审时，在第 1 节的交接信息中补充候选建议、证据定位、覆盖缺口、反证和关键推断。评审者按定位回查必要证据，不只复述取证摘要；实质修订后针对性复审。需要的核查未能完成时，说明缺口和实际核查状态，不声称已验证或适合直接实施；未做独立评审不等于没有做主代理核查。

报告先简要说明目标任务、使用的 skill、证据覆盖及重要缺口，再按实际影响排序给出建议。每项包含：

- 问题、可定位证据与实际影响；
- skill 归因、反证及仍未确定的部分；
- 最小修改位置与方向；
- 预期收益、成本、适用边界和评审状态。

数量由证据决定，不设必须产出的条数。合并同一原因的重复问题；不要列出被筛掉的琐碎候选。将“有证据支持的建议”“已检查范围内没有值得优化的问题”“证据不足无法判断”分开表达，它们可以分别适用于不同问题或区段。

完成复盘不等于授权实施。用户要求修改时，保留证据、范围和待核实事项再进入实施；提示文档采用静态审阅、一致性及包装/链接检查，脚本允许功能测试。不得创建、保留或运行模拟会话行为测试；静态检查通过不证明 prompt 行为可靠，实际收益通过后续真实使用观察。
