# 来源选择与工具边界

按本次问题字段选择入口，不给整个平台质量背书。旅行攻略和吃喝推荐默认先查小红书、B站与高德社区分享，再用高德 POI/路线核对可导航身份、地址和交通；官方信息只承担营业、运营和临时规则核验，媒体、Trip.com、博客和搜索结果作为补充线索，不得挤掉用户指定社区来源。先用社区发现，再到拥有该事实的来源核查；时效和冲突处理遵循 SKILL.md 第 2 节。

| 要解决的问题 | 优先路径 | 采信边界 |
| --- | --- | --- |
| 身份、位置、周边、转场 | 高德具体 POI、路线；运营方入口信息 | 查到 POI 不代表营业确认；地点中心不等于出入口 |
| 营业、预约、票务、临时调整 | 运营方官网/官方公众号、目标日期公告 | 区分整个场所与独立设施 |
| 实探与玩法 | **优先小红书、B站优质作者、高德社区分享/评价**；再用当地个人长文补充 | 选有到访日期、现场细节、同行条件与可印证记录的内容；不替评论真实性背书 |
| 系统旅游经验 | 可读取的马蜂窝/穷游长游记、携程历史游记 | 逐篇审阅；携程旧游记不可视为持续更新来源 |
| 徒步、路面、爬升、补给 | 8264/两步路实走记录；公园/管理方公告 | 成人体力不代替儿童适配；轨迹不证明通行许可 |
| 本地新去处与活动 | 当地媒体原稿、区级文旅、城市活动汇总，再回举办方 | 本地宝等汇总负责发现 |
| 周边小型活动 | 公园、少图、文化馆、青少年宫、书店、商场、自然教育组织公告 | 根据本次需求逐个核发布主体、场次与适用条件；商业运营者需另外核产品规则 |
| 酒店、机票、门票、套餐 | 已接入的美团旅行助手、飞猪及商品详情；酒店比价可用去哪儿网页补充 | 供给/推荐不等于体验证据；返回文案及价格需核实际产品与权益，比价标注查询时刻与价格口径 |
| 团购与优惠 | 美团/点评/抖音实际可读商品详情、商家说明 | 页面能读到的权益才参与比较 |
| 天气与交通条件 | 高德天气、气象部门/中国天气网；铁路/轮渡等实际运营方 | 查目标区域和发布时刻；赶海按需另查当地潮汐，地图预计耗时不是承诺 |

## 大众点评结构化观察

使用已授权 iPhone 查询后，先读取提取 JSON，再将门店记录视为候选发现线索：

```bash
node <skill-dir>/scripts/dianping-observations.mjs /tmp/dianping-result.json
```

适配器接受 v2 分页观察及旧 v1 单屏观察，校验 App 身份、查询时间、字段值范围与 v2 证据引用。旧 v1 强制要求复核；新 v2 从原始 observations 重新检查字段、置信度和复核原因，保留 failure、coverage、artifacts、每个字段的 recognitionConfidence、歧义标记和 evidenceRefs。extractionNeedsReview=false 仅表示当前抽取规则未发现疑点，不代表内容正确或事实已核实。

先检查 status 与 coverage.stopReason；partial 结果只可使用已成功捕获的页面，遇到验证或登录不得继续滚动。默认最多 3 屏，范围以 capturedScreens 为准，exhaustive 始终为 false；达到上限、重复页或没有新增候选均不证明全站结果已经查完。字段存在比例为 fieldPresence，不是可信度评分。低识别分数不应通过正则或固定权重人为提高。

消费规则：

- 先把 App 记录用于发现名称和候选分店。逐个打开决定性候选，核对完整门店名和所在商圈；仅因名称相似、距离近、排序靠前或出现在“推荐”区，不算身份已确认。
- 评分、评价数、人均、优惠、距离和营业状态都是查询时页面观察值。只有当前回答需要的字段才继续核验；动态价格/营业状态应以当前具体门店或产品页面为准，无法核验时保留平台观察标注和查询时间。
- App 记录不提供原帖/单条评论的可引用链接，不单独作为体验结论的充分依据。需要评价内容时进入对应门店的具体评价或原始内容页面；页面无法打开就说明证据缺口。
- 抽取器返回的记录不是推荐排序。推荐仍按本文件来源规则、当期信息、用户约束和同口径比较生成；未核实字段不参与确定性取舍。

## iPhone 详情与小红书卡片

按 yjx-iphone-app-ops 的[原生内容操作](../../yjx-iphone-app-ops/references/native-content.md)运行。点评详情 fields 只表示当前页地址/营业摘要，原文字行和置信度仍要保留。分享二维码输出的是实际平台跳转链接，先打开核目标；网页要求登录时，标记访问受限。

小红书输出是原生卡片观察，cardText 可能含标题和摘要，authorObserved/timeObserved 是页面文字；相对日期须结合 readAt 与用户时区解读。广告和 AI 汇总已从候选排除，但这不证明剩余卡片内容可靠。url、noteId 为空时明确缺口，继续打开原帖取得正文与真实分享入口；没有读到原帖就只报告发现线索。

## 社区内容读取

- 小红书站内搜索后进入原帖，读取正文、必要图片、评论与作者回复；评论可能揭示宣传中的设施尚未开放。取页面真实链接，不猜帖子地址或复制账号校验参数。标题“避雷”或一句负评不足以推导具体问题。
- 用户给出吃喝类帖子时，把其中的店名、菜名和价位当作发现线索，并主动查同片区的近期实探、媒体和平台店铺页，补齐可导航门店、分店、招牌菜、营业与排队条件。只读到品类或摊位画面时，保留“按品类找”的层级，并另找可核店铺；评论里的 AI 汇总或一个网友点名不能自动升级成门店事实。同一餐类给出足够行使选择的店铺与替代，不只复述原帖。
- B站等视频候选按播放与评论量、发布时间、作者在地相关性排序，仅决定读取优先级，不进入推荐强度；标题、简介、章节只用于发现候选。字幕可得性用于预估读取成本，先判断转写或 OCR 回退是否可行，再决定是否排除。
- 体验类注意事项（座位、气味、视野、讲解位置、排队、晒、噪音等）须来自实际攻略、实探或评价原文，保留出处与到访条件；项目名称和常识不能补成体验结论，无原文依据时标未知或省略，不写通用提示。
- 个人公众号/博客按具体内容验证作者与实探；纯榜单拼凑、缺乏经历证据、隐性招徕或反复错误的内容不进入优先入口。访问受限与内容质量差分开判断。
- 在已有工具可完成时，不新增 OpenCLI、Agent-Reach 或非官方抓取后端。当前用户不采用知乎、百度普通搜索与博查；抖音不进入常规视频解析路径。

## 视频读取完成标准

用户要求看、解析或推荐视频时，先取得匹配该视频/分集、覆盖用户要求范围的完整字幕（默认全片），并读完正文，再评价内容或推荐；追问“还有哪些”时，对每条新增视频执行同一标准。标题、简介、章节只用于发现候选，尚未取得并读完字幕的条目不能列作已解析或内容推荐。

1. 核对视频/分集身份、时长、字幕语言与人工/自动类型，取得非空、带时间的字幕正文。字幕菜单可见、工具导出成功或文件已存在，都只证明各自状态，不证明已读完。
2. 按时间顺序读完全文；长稿分批读取，工具输出截断时继续读取剩余部分。检查覆盖范围和异常缺段，区分自然无对白与提取缺失。只有读完用户要求范围且没有影响理解的未解决缺口，才算完成。用户明确只看某段时按该段处理，并只报告该段；自行抽取片段不能称全片看完。
3. 攻略视频提到店铺、地点或地址时，提取原文名称、时间点及所在片区，主动尝试用高德、点评或商家资料查明真实全名、具体分店和详细地址。结合上下文及必要的该时间点招牌/地址画面校正字幕或 ASR 的错识；同名店、旧址与搬迁后的地址分别核对，不只照抄字幕，也不默认选择搜索首条结果。查不到或有多个无法区分的候选时，保留原文与疑点，明确哪些名称或地址未确认，不将猜测当作可导航地点。
4. 游玩攻略同时提取作者实际介绍的行程路线：起终点、途经点及先后顺序、各段交通方式、游玩与转场耗时、用餐/休息安排，以及推荐、跳过或绕行的理由，保留对应时间点。区分作者实际走过的路线与口头建议、可选支线；视频剪辑顺序不自动等于游览顺序，未提到的交通或耗时标未知。将路线作为查询结果中的证据，结合本次人数、体力、日期与返程安排说明适用性；需要把这些材料组织成行程时交给 [`yjx-travel-planning`](../../yjx-travel-planning/SKILL.md)，不在查询 Skill 内直接排攻略。
5. 交付视频结论时简要注明字幕/转写来源及实际读取范围，并给出支撑推荐理由的时间段；作者实际到访日期与视频发布日期分开。列出本次相关地点已核实的名称、分店、地址及依据，未确认项标明缺口；有相关路线时给出原路线与本次建议的取舍，地点双平台入口按主文件的交付规则执行。

字幕获取复用 [视频来源适配](../../yjx-video-course/references/source-adapters.md) 的身份核验和浏览器响应读取方法，只取证，不启动课程制作。独立字幕不可得时，优先按 [本地转写](../../yjx-video-course/references/local-transcription.md) 检查已有语音识别能力，取得覆盖用户要求范围的完整带时间转写并按上述标准读完；硬字幕 OCR 用于没有有效口述或补核地名。默认避免解析大量画面。

仍未取得正文或尚未读完用户要求范围时，明确报告“尚未取得字幕”或“仅解析了某时间段”，保留实际失败原因和可用证据；不称“已看完”“解析完成”，也不以免责声明将标题和简介补成内容结论。没有口述或字幕的纯实拍可以说明已观察的画面范围，但不冒充已完成字幕内容解析。

## 分支核查

- **门店/午餐**：核分店、菜系、午市、预算口径、入口和转场；按需求补座位、儿童椅、停车与厕所。用排队或拥挤经历影响选择前，核实际到访的工作日/周末、节假日及用餐时段；发布日期不代替到访日期，不同条件只作当次记录。围绕所选出口找店，避免推荐名称相同而动线不符的分店。
- **酒店**：核目标日期、具体门店与房型、床型床宽、实际入住人数及儿童年龄的接待上限，再比较房间面积、价格和权益；儿童免费使用现有床不等于该房型允许全员入住。区分平台价、会员价及含早人数。推荐前结合近期具体住客经历，分析与本次需求相关的卫生、隔音、设施维护和服务；核对房型、到访时间及具体情境，区分重复问题、孤立反馈和已整改事项。总评分、面积或品牌不能单独决定排序，也不默认所有用户对各维度的权重相同。用户重视早餐时，分别核丰富度、特色体验和到达便利；动物观赏或主题环境不能替代早餐品质证据。
- **乐园/度假区**：集团、度假区、具体园区与套餐分别核身份和适用范围；食品准入、身高限制、入园次数、有效日及早餐等权益以对应园区或具体产品规则为据，结论写明适用对象，不将一园规则推广到整个度假区。
- **参与方式**：同一地点的外围观看、入内参观、登临或体验项目可能适用不同规则。先明确本次推荐的参与方式，再分别核对应的费用、入口、预约与截止时间；交付只把适用于该方式的限制列为条件，其他方式单列为备选，不将售票或入场截止时间套用于外围观看。
- **优惠/套餐**：统一日期、分店、产品、人数、权益和退改口径，再核可用时段、节假日、预约、加价与账号资格。区分人均、起价、会员价、实付价；脱敏价格或未展开权益标未知，不猜价或称全网最低。
- **限时活动**：核年份、场次、年龄、报名入口及状态；活动回顾、往年场次、无年份或售罄商品不能当本周可报名推荐。常设去处单列。户外按场景核天气、风雨、潮汐与通行限制。

工具选择与官方接口权限另见 [接入范围](tools.md)，仅在检查工具或新增接入时读取。
