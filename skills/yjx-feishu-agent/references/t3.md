# T3 Code 接入与来源迁移

T3 接入使用运行中服务的正式 CLI，凭证由 CLI 自行管理。只发送到用户指定的已有 T3 会话，不创建新会话，不绕过 T3 恢复底层 Codex 会话。其他未映射的来源继续走原 Codex 适配。

## 配置与切换

先停止接收器，备份仓库外的 `feishu/bindings.json`；保留其他群、白名单、投递及入站账本。配置顶层 `t3Command` 为原生可执行程序及固定前置参数的字符串数组，按机器提供可选的 `t3BaseDir`。不使用 shell 包装器；Windows 可使用 T3 安装包原生可执行程序及其 CLI 模块，适配器设置 Electron 的 Node CLI 模式。安装更新后先只读核对入口；路径失效时停止，不猜替代程序。

在明确授权的单条群绑定中设置 `threadTargets`：键为已有的来源 UUID，值为 `{ "kind": "t3", "threadId": "22222222-2222-4222-8222-222222222222" }`。示例 UUID 是虚构值。默认绑定 `threadId` 仍为该群明确选择的来源 UUID；旧来源和当前来源可分别显式映射到同一 T3 目标。来源 UUID 是推送/引用登记的身份，T3 目标 UUID 是执行地址，不能混用。

任务或角色按 [主动投递的来源约定](outbound.md#命令与输入) 使用专用 `YJX_*_SOURCE_THREAD` 环境变量。变量值须为本群 `threadTargets` 中已核实的来源键，不以 T3 目标 UUID 替代；切换 Provider 或派发子代理时保持该来源配置。

映射只作用于配置它的群；无映射的引用继续按原来源处理。历史投递指纹和消息来源登记不改写。每条新入站在受理时将实际 `agentTarget` 持久化，后续变更绑定不能改变已受理请求的执行目标。别名指向同一 T3 目标时由宿主统一排队；每个请求的未知状态独立保留。

执行 `bindings.mjs check --chat <群ID>`，确认返回 `target.transport:t3`、目标 ID 正确、状态 `readable`，再启动接收器。检查只读，不提交任务，不代表真实飞书往返已验收。回滚时先停接收器，恢复已备份绑定并核对，再启动；保留全部最新请求及投递账本。

## 提交、反馈与恢复

每个 requestId 只提交一次，使用 `thread send <T3目标> - --json`，正文从标准输入传入。提交 RPC 有限等待，忙碌目标由 T3 自己排队；桥接不再用前一条请求的未决账本或残留目标锁阻止新请求。提交回执丢失只影响原请求，不自动重发、不换编号绕过，也不阻塞后续消息。

接收器将新请求提交、旧结果观察及飞书投递分开调度。观察和投递有独立并发、总预算和轮转退避；旧 unknown、失败的反馈和路由登记均不占新请求入口。T3 中正常运行或等待人工输入的任务仍遵守宿主队列，桥接不自动中断它们。

用户文案、拒绝反馈、DONE 与 CrossMark 兜底见 [处理反馈](processing-feedback.md)。队列满、受理异常与停止中的有效请求走独立拒绝反馈，不再只有运行日志。最终答案投递确认后才标记 DONE，已受理反馈不等于最终答案已送达。文字反馈失败使用原消息 CrossMark 兜底；两者均不可用时保存待反馈，连接恢复后按最新状态继续处理，不把日志视为用户已收到。

### 原运行结果

结果按已持久化的 runId 归属；没有身份时才用唯一完整 wireMessage 标记绑定。已有身份不能被另一轮复制的标记覆盖，普通助手文本、latestRunId 变化、线程空闲或时间经过都不能单独证明原请求完成或失败。

后台读取本机 T3 的正式 HTTP 接口 `/api/orchestration/threads/<id>`，协议头 `x-t3-orchestration-protocol: 2`。通过官方 CLI 签发仅 `orchestration:read`、有效期一分钟的临时身份，令牌只在内存中使用，查询后撤销；本机地址取所选 T3 数据目录的 `userdata/server-runtime.json`，只接受本机 loopback，不从认证数据库或编译模块提取密钥。按原运行状态、完成时间及同一 run 的非流式最终助手文本判断结果；后续运行开始不妨碍读取旧运行。接口不可用时可用 CLI 读取当前轮的明确结果，证据不足继续未知，不误判失败。

`agent.mjs status --request-id <原ID> --refresh` 只核对原记录，不提交任务或发送飞书消息。旧版推断得到的 `failed/NO_FINAL_REPLY` 允许受限重新核查；真实 TURN_FAILED/TURN_INTERRUPTED 不重新开启。绑定变化不改变原请求执行目标。

### 送达与重启

状态通知、最终答案和补送答案使用不同的稳定投递身份；相同投递冻结消息类型及正文后再发送。飞书回复 UUID 的去重保证为一小时：回执未知仅在这一保证内按原身份和原正文重试；过窗仍无法核实时保留待核查并给异常标记，不换身份重发答案。明确拒绝与回执未知分别记录。来源登记失败只重试登记，不能重新发送已送达答案。

新账本使用 `deliveryVersion:2`，保存执行、状态通知、答案送达与路由登记的独立结果。重启恢复这些记录的观察和待反馈，不重放任务；受理后尚未确认提交的记录也会生成明确反馈。历史旧版记录保留，不批量重发历史答案。停止时有界清理本地工作，未决记录保留到下次启动；停止本地观察不等于取消宿主任务。

本机只读接口已实际返回包含历史运行及消息的投影，支持后续轮次存在时读取原运行；这不代表每条业务消息的飞书客户端效果均已验收。T3 投影目前可能省略助手消息的 `phase`，因此“线程已 completed”或“最后一条 assistant 文本”都不能单独证明最终答案：同一 run 有多条未标注 phase 的助手消息时，适配器保持 `unconfirmed/awaiting_final`，不把进度说明投递到飞书；只有明确标记 final，或历史中只有一条可用助手消息时才接受文本。T3 归档目标仍阻止该次提交，不调用 Codex unarchive；旧卡片投递门禁按 outbound 协议独立处理。
