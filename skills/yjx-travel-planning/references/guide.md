# 攻略资料与呈现

## 选择交付方式

基础攻略的目标是让读者读完后在脑中形成完整的旅行思路，同时在底层沉淀可筛选、可动态替换的结构化资料。即使尚未确定具体出行日期或时刻表，基础攻略也必须交付**完整思路三要素**：

1. **空间与片区格局**：讲清目的地分哪几个核心片区、各片区主打什么体验、彼此方位与通行距离尺度（如“新农贸市场内摊位集中，步行约10–15分钟可达解放路老街店”；证据不足时用文字如实说明空间关系，不杜撰未核实的入口或距离）。
2. **有明确取舍的精选梯队**：结合同行人条件，主动将候选收敛为“主推核心 / 顺路可选 / 建议跳过（附一句跳过原因）”，帮读者完成初筛，而不是把数十条原始节目表或全量店铺名单原样平铺让读者从零挑选。
3. **1–2 条典型串联动线草案**：按半日或单日顺路逻辑给出“从哪进 → 先抓什么核心体验/吃什么 → 步行或乘车几分钟转到哪里 → 如何收尾或替换”的默认玩法靶子。典型动线草案不绑定未定的具体出行日期、车次和钟点；当用户要求编排单次具体日程时，再使用 [行程攻略交付结构](planning.md#攻略交付结构) 落到具体日期、钟点锚点与分段导航。

## 组织可读内容

攻略页面采用**“上层连贯导读 ＋ 下层结构化数据库视图”**双层架构：

- **上层连贯导读**：在页面上半部用连贯的章节、总览地图与紧凑动线串讲清“空间格局 → 精选必玩必吃（含为什么去、点什么、关键门槛、双平台入口与原帖链接） → 典型串联动线草案”，让读者无需跳转多层数据库卡片就能从头读到尾建立完整画面。严禁把“仅嵌入几张数据库视图”当作攻略正文。
- **下层结构化数据库视图**：在上层导读下方嵌入「场所」「体验项目」的画廊、列表或分类筛选视图，承载全量候选与次要备选，供读者批量直观浏览，并在旅途变更时按片区、类别或角色快速抽换。面对大量候选（如景区数十个演出、多条街区店铺）时，正文主线只展开主推核心与关键顺路项，全量长表收进下方数据库视图或底部折叠区。

先明确攻略要服务的体验。用户提供的社媒帖子、视频或榜单是发现入口，不是本次攻略的范围上限：它提到吃什么、看什么，就以这些名称为起点，调用 `yjx-life-query` 查当地近期实探、评价和媒体材料，找出可导航的具体店铺、分店、招牌菜、营业与排队条件，再与用户已给的地点一起取舍。用户特别重视吃喝时，吃什么、在哪里找和如何选择是基础攻略的重要内容；编排行程后再关联当天的用餐安排，不能只复述原帖，也不能因原帖没给店名就停止检索。

吃的名称先分成两类写：能核到具体门店或固定位置的，给导航入口和明确的“点什么”；只有品类、画面或无名摊位的，写清来源已支持的寻找方式、售罄条件和替代，不能把评论里的名称补成已确认门店。基础攻略保留有价值的候选、差异及待核线索；编排单次行程时，才将相关候选落实为“吃、替换或明确跳过”，并关联当天安排。

**就地呈现证据并严控免责噪音。** 在各门店、食物和地点条目旁保留支持该条目的可追踪原帖或原视频链接；有可用实拍图片或视频画面时，尽量直接展示并标注作者、来源和对应内容。视频链接带具体时间点，先核对时间点确实对应所述内容；实测跳转效果，并区分未实测或平台不支持的情况。无法取得原帖链接或准确时间点时，在该条目说明缺口，不用搜索首页、无关图片或猜测时间替代。来源清单可补充完整资料，但不能代替条目旁的入口。

阅读面与核验面彻底隔离：正文只保留**可执行结论、简短取舍理由，以及真正会改变行动顺序或可行性的硬条件**（如“2026年9月实拍15元”“入园先查当日场次再定这两站先后”“含爆破巨响，2岁幼童视现场反应进退；需预约”）。废除不改变实际行动的常识性自保免责话术（如“看表演不等于游客能上台”“图示场次不代表当日承诺”“不是景区官方适龄认证”）。

信息价值决定收录，来源决定配图要求，具体提取与身份核验使用查询 Skill 的来源交接规则。无图但有具体依据的文字条目正常呈现；可用实拍帮助理解内容，图片缺失不单独决定体验价值。影响选择的未知就地说明，内部提取状态和查询过程留在资料维护面，不作为读者页面的骨架。

## 资料保存与复用

在本次已授权的目标页面或资料范围内保存；探索材料先留在任务范围，不自动进入全局地点库或长期档案。优先复用目标工作区既有的「场所」「体验项目」「信息来源」数据库与等价属性，缺失时最小化补齐支持筛选与旅途动态变更的**规划属性**：

- **所属片区 / 动线节点**：标识该场所或体验位于哪个地理片区或串联节点（如“角美新农贸市场内”“解放路老街”“万岁山·东区”），支持按空间聚类筛选。
- **推荐角色 / 梯队**：区分 `主推核心`、`顺路可选`、`条件备选` 或 `建议跳过`，让数据库视图能直接筛出主线与同片区替换池。
- **适用时段与关键限制**：简明记录影响排期或替换的硬条件（如“仅限早市”“需预约场次”“身高/年龄限制”“预计停留时长”）。

按用途在页面下层配置画廊、列表或按片区/角色筛选的视图；文字分组、画廊展示与筛选表服务于批量浏览和动态替换，与上层连贯导读配合使用。经验的具体字段与信息性质沿用 `yjx-life-query` 的来源交接结果，避免在正文和属性中维护两份完整副本。

结构化摘录作为日常读取入口；完整原文/字幕独立保存到正常读取攻略或摘录时不会连带返回的位置，并保留可访问引用及已读范围。Notion 折叠只改变界面展示，不能单独保证全文不被工具返回；选择独立页面或文件后，回读摘录入口确认实际返回范围。再次取证按查询 Skill 的复用规则进行。

改变资料布局前读取现有记录、关联和嵌入视图，区分库本体与链接视图；清理旧入口时保留仍需使用的资料和引用。删除、移库或改写遵守当前授权，不因优化阅读布局扩大范围。保存后回读条目、经验关联、来源入口、图文对应和全文引用，确认摘录可独立使用；明确报告局部失败。
