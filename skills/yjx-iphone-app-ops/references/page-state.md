# 页面状态与恢复交接

## 职责与交接

本 skill 负责当前设备、App 页面、授权操作及局部恢复；跨会话上下文保存、任务进度持久化和整项任务预算由调用方及其上下文保存机制负责。本 skill 不建立独立任务账本，不规定整项任务的默认时限，也不触发上下文保存来替代调用方编排。

中断或恢复后按[受阻与恢复交接](contract.md#受阻与恢复交接)汇总已有结果；缺失项明确写未确认，不为交接补发设备命令。设备锁、session 缓存及 unknown/reset/creating 标记仍由原控制链路管理；它们是防止重叠命令的运行状态，不是业务任务记录。

再次接到目标时，先核对授权、设备 owner 及会话标记，再确认当前页面和动作后置条件。旧选择器、滚动位置和截图坐标只作线索，重新确认后才能使用。原动作效果未知且后置条件未能证实时，该动作及依赖它的步骤保持受阻，不因“未完成”重发；按[结果复核](operations.md#动作结果复核)返回证据，由调用方决定业务后续。

## 局部等待与恢复

沿用各命令和恢复分支已有的等待、重读及会话替换上限。同一局部故障处理不通过外层循环反复重开相同预算；耗尽后返回状态与原因，由调用方重新评估。加载等待与控制链路恢复分别处理，不因内容加载慢就替换 session。

调用方明确给定时限时，在现有接口支持范围内限制本次等待或恢复，并说明实际覆盖范围。当前 CLI 没有跨命令总预算执行器，不能声称已强制执行整项任务 deadline。局部等待到期后不发新轮询；已发出的命令仍等待自身传输 deadline，不缩短在途保护或重叠发命令。停止等待不能证明动作未执行，预算也不授予重启服务、终止 App 等额外权限。

## 页面状态判断

先通过目标 App 身份和凭据/安全门禁；存在未决请求时先恢复链路，按[任务恢复决策](recovery.md#任务恢复决策)处理。随后综合页面身份、加载信号和目标条件判断，不单靠一张截图或一次元素缺失。

| 状态 | 必要证据与下一步 |
| --- | --- |
| 仍在加载 | 有加载标识、骨架屏或连续观察到内容推进；保留同一步骤等待窗口，有限等待目标条件，不据此重启 session |
| 内容就绪 | 关键内容完整、加载状态结束且对象与本次请求匹配；按目标读取或操作，不把旧列表当本次搜索结果 |
| 明确无结果 | 已确认本次请求/筛选条件，加载结束且有明确空结果提示；只对该范围报告无结果 |
| 部分内容或疑似旧内容 | 仅部分字段加载、列表仍属旧关键词，或无法确认更新；保留已读字段，指出未确认部分，继续等待或独立观察，不拼接成完整新结果 |
| 交互遮挡或页面偏离 | 键盘、弹层、滚动位置、返回层级或刷新使目标不可见；先确认页面和遮挡来源，必要导航属于授权范围且不会丢失编辑内容时才处理，然后重新定位 |
| 读取能力不足 | App 状态可确认，但树、DOM、OCR或解析器不足；按读取方式补证据或修复解析器，不推断业务对象不存在 |
| 无法分类 | 空白、静止、黑屏或信号冲突且无充分加载证据；记录“页面状态未确认”，预算内有限重观察，不将根因直接归为网络波动 |

页面在加载或更新时不重复提交、重发搜索或点击原提交按钮；下一次动作必须有独立依据。即使加载图标持续存在，也受本次等待窗口和调用方明确给定的限制约束；等待耗尽只报告当时状态。键盘收起、关闭弹层、返回或刷新可能触发提交、丢失草稿或改变列表，先判断影响；同名目标仍需核对对象身份与唯一性。
