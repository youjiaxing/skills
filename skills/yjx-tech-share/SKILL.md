# yjx-tech-share

将内部技术、AI 工具或工程实战经验打磨为适合现场主讲的单文件离线 HTML 幻灯片与双屏同步提词台。

## 职责边界

- **案例来源由主讲人掌控**：案例与素材由主讲人直接指定、通过对话共同梳理，或仅读取主讲人显式点名的项目文档与产物文件。不扫描或挖掘本地会话记录（如 `.codex/sessions`），也不主动盲翻后台运行目录塞入主讲人未点名的子用例。
- **不负责**：视频课程字幕转写与笔记（归 `yjx-video-course`）、日常单点代码调用链或局部机制微型图解（归 `yjx-show-me`）、对外商业融资路演或位图海报 PPT 生成。

## 工作流

### 1. 增量看点梳理与分享确认卡（硬门禁）

编写任何演示 HTML 前，先与主讲人梳理案例并做**增量价值检查与跨页去重**：

- **跨页去重**：核对每个候选案例比前一个案例多展示了什么新场景、新机制或新经验。若两个案例证明同一件事，或某个例子已在“上手演示 / 过程回放”页完整讲过，主动提示合并、融入同一页或替换，不把同一案例拆在前后多页重复展开。
- **聚焦真实卡点与解决思路**：不套用固定案例数量或强制层级模板；按当次分享目标（用法普及、进阶排障或架构复盘）弹性组织深度，引导每个案例讲清“当时遇到了什么棘手卡点或边界 ➔ 为什么常规做法不好使 ➔ 这次用了什么思路或巧妙手段解决 ➔ 沉淀下什么可复用的判断”，将具体协议号、命令参数或产物退为支撑结论的次要证据，避免写成“调接口 A ➔ 发协议 B ➔ 出绿报告”的同质化操作流水账。

整理出结构化的**「分享确认卡」**提交给主讲人：

| 字段 | 内容 |
| --- | --- |
| 分享场景与受众 | 团队角色、预期时长、主讲形式（现场翻页主讲 vs 会后群聊自助阅读） |
| 核心主线 | 一句话说明本次分享希望同事带走的核心判断或行动 |
| 分页大纲与案例清单 | 逐页列出：`页码/ID` · `页面标题` · `本页核心结论` · `对应演示案例及增量看点` · `拟内联的过程回放或结果产物` |

**完成标准（硬门禁）**：必须先提交「分享确认卡」并获得主讲人明确确认（确认案例熟悉且结构有区分度）；未获主讲人明确确认，不得进入 HTML 编写阶段。

### 2. 构建观众屏与内联演示产物

按已确认的「分享确认卡」构建单文件离线 HTML 幻灯片（默认支持键盘 `←` / `→` / `Space` 翻页与 `F` 全屏）：

- **100% 离线单文件可分发**：使用本机系统字体栈（中文优先 `PingFang SC`, `Microsoft YaHei`, `system-ui`；等宽优先 `JetBrains Mono`, `Consolas`, `monospace`），严禁引入 `fonts.googleapis.com` 等阻塞首屏的外部字体或外网 CDN。凡需在现场点击查看的本地报告、图表或截图，统一以 Base64 Data URI 或内联 JSON/HTML 数据打包进同一 `.html` 文件，确保通过群聊（如钉钉群）发给无本地环境的同事也能直接双击打开交互。
- **过程回放与结果产物并重**：分享研发工具、AI 技能或工程流程时，除内联最终结果报告外，提供可交互的“实际使用过程回放”（如还原“人怎么输入 ➔ 工具怎么执行 ➔ 结果怎么返回”的分步浮现面板，配 `↻ 重播动画` 与 `⚡ 全部展开` 控制），并与案例页做好分工或合一，不重复叙述同一案例。
- **页面主次与字号克制**：
  - **极简封面**：封面仅保留主标题、副标题与核心案例看点预告；不堆砌未铺垫的底层术语，严禁把“100% Offline Single-File HTML”等交付物工程验收词写上观众屏。
  - **一页一主角**：每页只围绕一个核心判断展开，卡片只保留结论锚点与核心证据，将完整背景与解释退入提词台，保证投屏远读字号充足、留白清晰。
- **平实克制的工程师叙事**：结合团队真实的日常工具链（如已有作弊器、IDE、常用沟通工具与实际工作区入口）客观对比；实事求是陈述收益，不夸大人工耗时，不使用贬低测试或协作同事的拉踩措辞，不编造与真实机制矛盾的说法（如把“AI 代写配置文件”说成“不用写任何配置文件”）。

**完成标准**：观众屏所有页面与「分享确认卡」一致，过程回放与内联产物均可在离线状态下直接点击交互，屏幕上无工程验收自夸词与外部网络请求。

### 3. 编写双屏同步提词台与三拍口播稿

观众屏默认隐藏所有讲稿；按 `P` 键（或点击右下角低调入口）弹出独立的演讲者提词窗口：

- **`file://` 兼容的双窗口同步**：为确保同事或主讲人在 `file://` 本地文件协议下双击打开仍能可靠同步，优先通过保留的 `window.open` 窗口引用与 `window.opener.postMessage(..., '*')` 双向同步当前页码，同时辅以 `BroadcastChannel` 与带 `try/catch` 保护的 `localStorage` 事件；当浏览器拦截弹窗时，观众屏保持不显示讲稿，只给出简短提示和重新打开入口；页内抽屉仅在主讲人主动开启“单屏演示模式”时使用。提词窗支持字号调节（`A-` / `A+`），且每次翻页自动将备注区滚动回顶部。
- **左栏极简提纲 + 右栏三分离救场保底稿**：提词台左栏列出本页 2–3 条核心意图，右栏按页面卡片/区域分段提供可直接对照念出的「救场保底口播稿」。每段保底稿严格拆分为三个视觉与语义独立的部分：
  1. **独立动作提示徽章**：将鼠标指向、点击切换或手势提示放在独立的 `[🖱️ 动作提示（只看不念）]` 徽章块中，严禁将动作指示混入台词正文。
  2. **三拍视线引导台词 + `<mark>` 页面原词选择性高亮**：
     - 按**“定向（Orient，先告诉听众看哪一栏/哪张卡）➔ 指重点（Point，原样念出页面卡片上的核心锚点词）➔ 落结论（Land，用自然口语解释背后的工程原因与判断）”**组织句子；
      - 每个需要引导观众看页面内容的口播段选择 1–2 个对应的核心原词或关键数值，原样嵌入台词并用 `<mark>` 亮黄色高亮；口播正文补充原因、判断和结论，纯转场或补充判断可以不重复页面文字；
     - 严禁每页机械重复“这一页讲的是…”、“本页主要展示…”等报幕式开头。
  3. **独立跨页转场句**：在每页提词底部单独设立 `[⏭️ 转场句]` 区块，用一句话挑起下一页要解决的问题后再翻页。

```html
<!-- 右栏单段救场保底稿结构示例 -->
<div class="script-block">
  <div class="action-cue">🖱️ 动作提示（只看不念）：鼠标指向“问题”卡片，讲完后点击“查看过程”</div>
  <p class="spoken-line">
    大家先看这张<mark>问题</mark>卡片。这里真正要解决的不是多点几次操作，而是先把历史状态和本次验证隔离开；所以我们让工具按固定步骤准备干净的测试状态，再把关键结果和预期逐项对照，避免把环境残留误判成业务结果。
  </p>
</div>
<div class="transition-cue">⏭️ 转场句：单个问题可以先隔离状态，那遇到步骤更多、分支更复杂的场景，怎样让验证过程仍然可控？我们看下一页。</div>
```

**完成标准**：每页均具备与 slide ID 一一对应的提词数据；需要引导观众看页面内容的口播段包含必要的 `<mark>` 页面原词锚点，口播正文补充页面未展开的原因与判断；动作提示与转场句完全独立于念稿正文。

### 4. 交付前静态与交互验收

针对生成的演示 HTML 文件执行以下检验（仅验证生成的演示 HTML 产物，严禁为技能 Markdown 文本编写测试脚本）：

1. **零外部阻塞与脚本语法检查**：确认 HTML 内无 `fonts.googleapis.com` 等外部阻塞链接，提取全部内联 `<script>` 块通过语法解析（如 `new Function` 零报错）。
2. **双屏提词与离线交互核验**：验证离线打开 HTML 后首帧即刻渲染；验证按 `P` 键打开提词窗、主副窗口双向翻页同步、翻页后备注自动滚回顶部、`A-/A+` 字号调节及弹窗拦截降级提示正常；验证页面内所有过程回放 Tab 切换、动画重播/展开按钮及内嵌报告弹窗映射全部有效。

**完成标准**：上述静态与交互验证全部通过后交付最终单文件 HTML 路径，并简要说明页数、内联产物范围及快捷键用法（方向键翻页、`P` 键打开提词台）。
