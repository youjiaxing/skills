# iPhone 地点双平台入口

具体景点/门店配套“高德地图｜大众点评”，以 iPhone 使用为目标。执行下列步骤，缺项按末节降级，不猜平台标识。

## 取得标识并生成

1. **取得高德标识**：从本次工具或真实详情页取得目标 POI ID，并保留来源；需要具体入口时查入口 POI。
2. **取得点评原链接**：找对应门店，核城市、全名、分店与地址，取得真实分享链接或详情页。保留原链接，不从高德 ID 推导点评 ID，不拷入账号验证或登录 URL。
3. **生成与格式校验**：使用 [链接脚本](../scripts/place-links.mjs)：

```bash
node scripts/place-links.mjs --name '地点或分店全名' --amap-poi '实际取得的POI ID' --dianping-url '实际取得的点评HTTPS链接'
```

命令从 Skill 目录执行，或将脚本路径替换为绝对路径。参数作为数据正确转义，避免把不可信店名拼成 shell 代码。缺失平台时省略对应选项，脚本返回 `null`；不把未取得的链接补成示例值。

脚本依据[高德官方单点 URI](https://developer.amap.com/api/uri-api/guide/mobile-web/point)生成 HTTPS 入口并尝试唤起 App，校验实际已见的点评 `/shop/`、`/shopshare/`、`/shopinfo/` 店铺链接或 dpurl.cn 短链的格式，保留点评原始参数。脚本不联网，格式兼容不代表目标或手机效果已验证，仍需分别核验。其他官方分享格式先核原链接及目标，再评估脚本兼容；不为通过校验改写分享参数或拼未经验证的点评私有 scheme。

## 分层核验与降级

- **格式**：脚本通过，仅证明 URL 与平台格式符合检查。
- **目标**：打开最终页面核同一城市、地址及分店，短链检查重定向；公园入口与整体、酒店与其中餐厅分别确认。登录墙只记访问限制，不能算目标正文已读。
- **手机**：在 iPhone 实际点击，确认是否唤起正确 App 及落到正确地点。首次尚未手机实测时只称“地点入口，手机唤起未验证”；桌面跳转不作为手机结果。宿主聊天、Safari及App安装状态可能影响唤起。

**缺口处理**：缺链接或目标访问受限时，说明缺哪一平台/核验层级，提供已核全名、分店、地址及仍可用的 HTTPS 入口。名称搜索明确标“搜索入口”；只在两边实际取得对应链接后才称双入口完成。

如需导航，用当前高德工具输出或[官方路径规划URI](https://developer.amap.com/api/uri-api/guide/travel/route)，确认出行方式和目标入口。此处地点标注链接本身不代表已生成导航路线。

## 高德单地点收藏

用户明确要求收藏某个已核实的单地点时，可通过已登录的普通高德网页版操作账号收藏。它不同于旅行地图加点，不代表该地点已进入行程；不把普通推荐自动全部收藏。

1. 优先使用内置浏览器打开已核实 POI 的地点详情，核对名称、分店和地址。用户提供当前页面时，尝试连接该页面；连接失败与高德未登录分别判断，限制结论限定到实际检查的入口和会话。
2. 检查现有收藏状态；已收藏则保留。未收藏时点击详情页的“收藏”，读取明确反馈并检查星标状态；若出现登录或验证，按访问限制规则处理。
3. 刷新或重新打开同一 POI，确认收藏状态仍保留。网页收藏与手机同步分别验证；未在手机检查时，不声称 App 已同步，也不假定已归入指定收藏夹。

2026-10-21 已在内置浏览器实测：地点详情点击收藏后提示“已收藏”，刷新后金色星标保留；未验证手机同步、指定收藏夹或批量收藏。
