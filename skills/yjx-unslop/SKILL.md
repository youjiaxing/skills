# yjx-unslop

让读者理解当前问题并知道如何判断或行动。按任务选择篇幅、结构与表达形式，在一次交付中完成内容组织和检查。

维护本技能前读[维护说明](MAINTENANCE.md)；普通使用不加载维护和来源历史。

## 1. 确定这次要交付什么

从请求、有效上下文和目标材料判断读者要理解、判断、查找还是执行什么。复用已明确的目标、受众与格式；只有缺口会实质改变结果时才问，不让用户代查已有材料。

- **生成新内容**：以当前任务、已确认决定和证据为依据，选取服务本次目的的信息；不把全部上下文转录给用户。
- **修订已有内容**：读完整个约定范围，固定原稿及获准补充为核对基准。上一轮或指定文件已明确时直接使用；无法完整读取就说明覆盖范围。审阅只给建议，用户要求修改才写回。

按实际工作读取对应参考，不预加载全部规则：

| 当前工作 | 参考 |
| --- | --- |
| 跨段去重、整篇修订、调整章节或论证顺序 | [结构编辑](references/editing.md) |
| 报告、验收结果、HTML 内容组织或区域重排 | [报告组织](references/reports.md) |
| 代码机制走读，或需要用图、树、代码、微型 diff 直观解释关系 | [图示与代码表达](references/visuals.md) |

## 2. 先组织内容，再写句子

决定读者最先需要的答案、状态或动作；解释所必需的定义和前提放在使用它们之前。遵守当前专业工作流的提问、协议与交付格式，不强套统一的“结论—原因—证据—下一步”模板。

每段、每节和每个区域承担明确作用。合并同义复述和未增加理解的换角度展开；一段同时包办不同问题时拆开或移动。先处理结构，再润色措辞。

对重复内容判断其作用与删除损失：

- 新条件、因果、后果、实测结果或独立证据有实质作用时保留；重复术语不等于重复信息。
- 摘要承担概括和导航，正文提供支撑；纯粹再说一遍的预告、收尾和修辞例子可以删。
- 删除会使读者无法理解、判断、复现或执行的信息，留在正文或可明确到达的查证位置。用户明确要求摘要或裁剪时按其范围处理。

问题报告带上判断所需的预期、实际及已知原因；阶段交付联系总目标，区分本次完成、范围内剩余及下一步执行方。只补当前用途缺失的必要内容，不为每次回复增加固定栏目。原稿未写但上下文已有的事实可补入；依据缺失就指出具体缺口。

## 3. 选择表达形式并成稿

文字直接交代对象、动作、条件和关系，使用完整自然的句子与稳定术语。按读者知识解释必要术语，不把字段标签、内部简称或临时命名串成需要解码的短语。字数、句长、标点或列举数量不作为编辑目标。

并列项用列表，对应关系用表格，因果关系用连贯说明。图或代码能降低理解成本时按对应参考选择最小有效表达；代码机制走读保留真实实现依据。邻近文字补图和代码未能独立说明的原因、条件与边界，不逐项复述视图。

保留必要的正式程度和作者声音；空话、机械对仗或通用赞美只有在缺乏具体作用时才改，不凭词表增删事实或编造个人观点。

## 4. 对照依据检查，再交付

先检查当前问题是否得到回答，必要关系是否齐全，阅读顺序是否连贯；再核对含义：

- 原依据到成稿：独立含义、数字与单位、范围、条件、否定、因果、时序、完成状态、责任、承诺、确定程度和归因保持一致。
- 成稿到原依据：新增断言与关系均有支持。生成新稿同样受证据边界约束；顺口或具体不等于真实。

多轮修订始终对照固定原稿和获准变更，不将上一轮改稿重定义为原始证据。引用、代码、命令、标识符、数据和链接目标保持准确；重排标题或结构时检查锚点与引用。修改会改变业务含义或超出用户要求时，保留原文并指出待解决之处。

当内容完整、重复已合并、表达清楚且含义核对通过时停止；没有问题的内容可以原样保留。默认只交最终所需内容，文件修改简述重要结果和剩余问题；用户或既有审阅流程要求时才展示编辑建议、对照或审计。

本技能不改变原任务的发布、发送、提交或部署权限；事实核查、专业判断和文件制作仍使用对应工作流。默认由当前 Agent 完成，不新增评分器、AI 检测目标、额外模型调用或强制多代理。
