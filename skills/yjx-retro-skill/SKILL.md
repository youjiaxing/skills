# yjx-retro-skill

由用户手动触发。主会话主持复盘，从本次实际损失与用户每一次纠正行为出发，寻找值得优化的已有 skill 问题、值得孵化或拆分的新 skill 机会，以及 Agent 协作文档与工程环境改进点。默认只调查并提出建议；新建、修改、拆分、安装、提交 skill 或操作外部系统属于另行授权的实施。

开始复盘时，先读取 `writing-for-agents` skill，将其作为评估与设计一切 Agent 消费文档（Skill、`AGENTS.md`、项目内文档及上下文指针）的统一标尺。

## 1. 确定证据范围与分工

默认复盘当前会话中已完成的实质任务（截止本次复盘调用前）；用户指定其他会话或任务时按指定范围。区分多个任务及其依赖，将复盘过程本身排除在被复盘任务之外。

主代理负责理解用户意图、安排调查、综合归因和交付建议。按被复盘任务的原始对话是否仍完整保留在当前上下文中分流：

- **当前上下文完整覆盖被复盘任务（未被压缩摘要替换）：** 直接以当前上下文中的用户消息、加载的 skill、工具调用与输出为主要证据，配合对相关 skill 文件、任务产物或 Git 状态的必要只读核验。全程由主代理单代理完成取证、归因、筛选与交付前核查；**不读取 [会话记录取证](references/session-evidence.md)，不查找或读取当前会话的磁盘原始记录（如 session JSONL），不启用取证子代理或独立评审子代理**。只要被复盘任务本身的原始对话仍在当前上下文中（即使更早的无关任务曾被压缩），即走本分支。若个别工具输出被截断或局部证据不足，直接记为证据缺口并限制结论范围，不回查磁盘日志或开启子代理。
- **被复盘任务在当前上下文中已被压缩摘要替换（含复盘前已替换或复盘期间被压缩），或用户指定复盘其他会话：** 当前上下文仍保留的原始消息与工具结果直接作为证据；对已被压缩摘要替换的区段或外部目标会话，读取 [会话记录取证](references/session-evidence.md) 定位磁盘原始会话记录并固定截止点（压缩摘要仅作定位线索）。将补读磁盘原始记录的只读工作交给上下文隔离（`fork_turns: "none"` 或平台等价机制）的子代理（Start every subagent with a fresh context window (do not fork the current conversation).），传入本 skill、目标记录定位、用户目标与约束、明确调查范围及返回要求；子代理分段读取并仅返回带定位的精简证据包，主代理按定位回查关键原文。若宿主无法使用子代理，主代理说明限制并自行分段读取必要区段。

按时间线建立覆盖记录，再围绕疑点检索：覆盖用户要求、**用户的每一次纠正行为**（显式纠偏、推翻或修正 Agent 输出与做法、中途叫停不当动作；普通方向切换先核实是否属于对偏差的纠正）、实际加载的 skill（未使用则记为无，并在已知可用列表与目标仓库相关范围内识别可承接职责的候选 skill）、关键工具结果、失败与返工、最终交付及核验。当前上下文分支使用消息顺序或事件定位；磁盘取证分支使用记录路径与行号或稳定消息 ID。记录已覆盖区段与缺失、截断或仅有摘要的区段。

完成条件：定位被复盘任务、实际使用的 skill（或确认未使用）、已覆盖区段内的全部用户纠正行为和证据范围，无法还原处标为缺口。综合整个会话的任务过程与用户纠正进行复盘：主责轨道覆盖 **Skill 层建议**；超出 Skill 层但经核实有价值的问题，按第 3 节其余层级分流。

## 2. 逐次复盘用户纠正与实质问题归因

结合错误、误解、返工、高昂工具调用成本、信息获取障碍与交付缺口寻找候选问题，并对已覆盖区段内**用户的每一次纠正行为**逐一复盘。必要时只读核验相关产物、来源、脚本或外部状态（不附带写入或重跑日志中的动作）。

评估用户纠正时，将“纠正是否合理”与“是否固化为通用规则”解耦（**并非每一次纠正都客观正确，但大概率符合用户偏好**）：

- **合理（指出真实偏差或符合用户偏好/当次合理意图）：** 指出了执行偏差、理解错位、低效默认行为、过严/缺失门禁，或表达了跨场景协作偏好。所有合理纠正均须追问“当时为何走到需要纠正这一步，后续如何从机制上防复发”。
- **不合理（受当时信息偏差或事实误判影响）：** 经客观事实与上下文核验，因当时信息不完整或误判状态给出，按其修改会导致错误或退化。
- **证据不足无法判断：** 因上下文截断或外部状态不可考无法核实，保留为待核实缺口。

对每个候选问题及每次合理纠正，核实事件过程、偏离的目标或稳定偏好、实际影响、当时适用或可承接职责的候选 skill 边界（尽可能核实执行时版本与可用状态），按以下类别归因（可记录共同原因）：

| 原因 | 处理 |
| --- | --- |
| 本次已使用 Skill 缺口、冲突、默认行为违背高频偏好或过严 | 分析防复发机制，按第 3 节第 1 层评估最小通用修改 |
| 已有但本次未调用 Skill 的触发或内容缺口 | 只读核验候选 `SKILL.md` 正文与职责边界：证实任务执行时已可用且允许调用的，归因为触发指针（`description`）/入口导航缺口或执行漏调；仅确认当前存在而无法证实当时可用的，作为**当前优先复用承接的已有 Skill 优化目标**，不倒推为历史漏调 |
| 可复用按需工作流缺失或现有 Skill 职责过载 | 具备跨任务复用价值、仅特定场景按需触发（不宜常驻 `AGENTS.md`），且经核验现有相关 skill 正文无匹配项（或塞入会导致职责过载）时，转入第 3 节“新建或拆分 Skill 提议” |
| 项目内文档 / Spec / 知识库缺口 | 属当前项目的运行时机制事实、架构决策或特定模块非显然边界的，按第 3 节第 2 层核验体系存在性与收录门槛后决定去向 |
| 项目/工作目录级或用户级全局协作层缺口 | 属仓库/目录级持续约束或跨项目个人通用偏好的，按第 3 节第 3、4 层分流 |
| 工具成本过高、信息可观测性不足或代码工程门禁缺失 | 当会话因昂贵工具调用、缺少日志/状态只读入口绕弯，或业务代码出现了本可由代码 Linter/CI/脚本拦截的机械错误时，评估补充只读辅助工具或代码工程检查；工具/环境客观限制则指出能力边界（仅在 skill 降级流程有问题时修改 skill） |
| agent 未遵守已有明确规则 | 记录执行偏差；仅当证据显示规则难以发现、表述冲突或违反 `writing-for-agents` 准则导致失效时才建议重构规则，否则作为“合理但无需新增通用规则”结案 |
| 单次任务特例 | 单次事故口径、当次临时改主意或随本次修复即失效的问题，直接排除在任何规则、Skill 与文档修改之外 |
| 原因未知或证据不足 | 列明缺失证据及对判断的影响，保留为待核实 |

对照已有保护措施和反证，已在后续版本解决的问题不再重复建议修改。

## 3. 筛选最小优化与四层落点分流

正式建议须同时具备具体证据、实质影响（或合理纠偏信号）、机制归因，以及在目标承载层内的持续复用价值（一次严重问题或一次合理纠正即可触发）。所有建议必须**剥离单次事故表象、具体报错值、当次对话原话及一次性 Bug**，并遵循 `writing-for-agents` 准则（精准触发指针、单一事实源、正向指令、剔除默认已遵守的 No-op）。

在落入文档前先做**机械 vs 判断分流**：针对业务代码或外部副作用逻辑的固定语法/命令/约束问题，优先通过项目既有代码 Linter、构建检查或可复用脚本拦截，把文档留给需要语境权衡的判断型准则；**严禁为 Markdown、Prompt、Skill、`AGENTS.md` 等文本型文件创建对应的测试文件或机械检查脚本**。

按作用域、信息性质与上下文常驻成本（优先落入按需加载层，减少每轮常驻负载），在以下四层中精确定位并遵守各自的准入与命名规则（后续报告提及跨出 Skill 层的落点时，**必须使用下述第 2–4 层的完整层级名称**，不得使用笼统的“全局 `AGENTS.md`”混淆项目级与用户级）：

1. **Skill 层建议（主责轨道，按需加载）：**
   - **已用 Skill 优化 / 已有未调用 Skill 补强：** 适用于本次已用 skill，或在已知可用列表与目标仓库相关范围内只读核验 `SKILL.md` 正文后确认可承接职责的已有未调用 skill（修改工作流步骤、`description` 触发指针、检查点、分流路由或降级规则）。改动须在该 skill 覆盖范围内跨模块、跨工单通用。
   - **新建独立 Skill 或从已有 Skill 拆分提议：** 须同时满足：（a）有跨任务重复触发信号与实质减负价值；（b）属特定场景按需加载的多步流程或专项规程，不宜常驻 `AGENTS.md`；（c）已只读核验相关候选 `SKILL.md` 正文确认无职责匹配项，或现有 skill 需按调用时机/序列边界拆分（若受可见范围限制无法完全排除外部重叠，标注“与现有 Skill 重叠关系待核实”）。复盘阶段**仅输出“新 Skill 概要卡片”提议**，不直接生成完整 `SKILL.md` 正文。
2. **项目内文档 / Spec / 知识库建议（跨出 Skill 层，按阶段/模块加载）：**
   - 仅当已有上下文、项目 `AGENTS.md` 或已加载 skill **已证实该项目维护了对应文档体系**时启用（严禁假设项目必有 Spec/知识库或凭空要求新建该体系）。内容须属跨任务复用的运行时机制、架构决策或业务模块非显然边界，剥离单次事故流水并符合该项目自身的收录标准。若项目无此体系或未达门槛，直接排除本层并继续评估其余层；若当前证据无法确认体系存在性、收录门槛或目标路径，记为“项目文档/Spec 层待核实（列明缺失项）”且不盲目全仓扫描。
3. **项目/工作目录级 `AGENTS.md` 建议（跨出 Skill 层，当前仓库/目录常驻）：**
   - 适用于当前仓库或工作目录（含子目录 `AGENTS.md`）内需持续遵守的协作约束、仓库拓扑、编译测试边界、提交规范或顶层导航指针。允许保留落实约束所必需的仓库或目录身份。
4. **用户级全局 `AGENTS.md` / 个人全局提示词建议（跨出 Skill 层，所有项目常驻）：**
   - 适用于跨所有项目复用的个人沟通偏好、问答格式、工具优先级、子代理协作策略等通用规则（如 `~/.codex/AGENTS.md`）。必须彻底剥离具体项目、仓库与业务特征。

优先选择最小改动：能通过澄清现有 skill 适用条件、锐化触发指针、调整默认动作、消除重复或删减过严约束解决的，不新建 skill。区分“无实质收益的字眼/目录挑剔”与“能稳定减少协作摩擦的用户偏好”，仅将后者去特例化后纳入建议。预期收益作为推断表述，缺失证据保留为待核实线索。

## 4. 核查与交付

交付前，主代理对照第 3 节标准核查每项候选建议的证据、合理性、归因、去特例化程度、职责边界及修改影响，剔除绑定单次事故特征或未达目标层准入标准的候选。当前上下文完整分支由主代理直接完成核查；仅在“被复盘任务已压缩或复盘其他会话”分支下，当主代理认为有必要或项目治理要求独立评审时，按第 1 节方式派发给未参与取证或形成建议的上下文隔离评审子代理（Start every subagent with a fresh context window (do not fork the current conversation).），传入用户纠正盘点、候选建议、证据定位、覆盖缺口与反证，由评审者回查必要原文并在实质修订后针对性复审。核查未完成时如实说明缺口。

报告采用两层密度：内部核查逐项覆盖全部用户纠正与候选问题；面向用户的正文按重要性压缩呈现，空分类省略，并严格区分“有证据支持的建议”“已检查范围内无值得优化问题”“证据不足待核实”。按以下顺序输出：

1. **任务与证据概况：** 目标任务、实际使用的 skill（未使用写无）、证据覆盖及重要缺口。
2. **用户纠正逐次盘点：** 用简短白话列出已覆盖区段内每一次用户纠正的定位、判断结果和处理去向（无纠正写无）。仅对转入建议、存在证据缺口或需用户决定的项展开分析：
   - **转入 Skill 层建议：** 标明子类（**已用 Skill 优化**、**已有未调用 Skill 补强** 或 **新建/拆分 Skill 提议**）并指向下方具体建议项；
   - **转入跨出 Skill 层的分流建议：** 按第 3 节精确标明目标层名称并指向下方对应建议项；
   - **合理但无需新增通用规则：** 简述已有规则覆盖、已修复或属单次特例的原因；
   - **不合理故不采纳：** 简述客观事实反证；
   - **证据不足待核实：** 说明缺失证据及影响（含“项目文档/Spec 层待核实”或“与现有 Skill 重叠关系待核实”的具体缺失项）。
3. **Skill 层建议（主责轨道，按实际影响排序，仅输出非空组）：**
   - **可直接采纳（单一明确方案）：** 仅限针对已有 Skill 且最小改法唯一、不改变核心意图或权限门禁、无明显副作用的建议。每项给出唯一方案：触发场景、证据定位与实际影响；skill 归因（已用缺陷、当时可用但漏触发、或当前优先承接载体）、防复发根因与反证；最小修改位置与去特例化修改方向；预期收益、成本、适用边界与评审状态。
   - **需讨论权衡（存在分支或代价取舍）：** 含存在多种改法/边界取舍的已有 Skill 建议，以及**全部“新建或拆分 Skill 提议”**。写明证据、归因与**待权衡的分歧点**，用从 `1` 开始编号的列表呈现候选方向（推荐方案置为 `1` 并附推荐理由与代价，其余附适用条件与不首选理由；**不使用 `Q<N>` 标题或 `yjx-grill` 提问块**）。其中 **“新建或拆分 Skill 提议”仅输出“新 Skill 概要卡片”**：
     1. **建议名称与调用方式：** 手动触发（`disable-model-invocation: true`）或模型按需触发，及 `description` 触发指针草案；
     2. **触发依据与实际影响：** 本次会话痛点、返工或用户纠正依据（附定位）；
     3. **核心职责边界：** 关键步骤/规则及明确排除项；
     4. **与现有体系的分工：** 与现有 Skill（含重叠待核实说明）及 `AGENTS.md` 的切分；
     5. **建议来源与候选切分方案：** 从零新建或从已有 Skill 拆分，以从 `1` 开始的编号列表给出立项/切分方案。
4. **跨出 Skill 层的分流建议（按需单列，仅输出非空组）：** 按 **可直接采纳（单一明确方案）** 与 **需讨论权衡（存在分支或代价取舍）** 分组（不使用 `Q<N>` 格式）；每项按第 3 节标明**精确目标层级与具体落点**、问题与证据定位、机制归因、去特例化修改方向（或从 `1` 编号的候选方向）、预期收益与成本。
5. **收尾决策分流提示：** 简短汇总决策状态（不自动调用 `yjx-grill`）：若仅有“可直接采纳”项，提示用户可直接确认实施；若含“需讨论权衡”项，点明哪些可直接确认、哪些需按候选序号拍板、调整边界或指定调用 `/yjx-grill` 深入讨论后再实施。

完成复盘不等于授权实施。获用户授权修改或创建文档/Skill 时，保留证据与已确认边界，按 `writing-for-agents` 准则实施，并通过静态审阅、一致性及包装/链接检查验证；仅对具备不可逆/外部可见副作用或失败难以手工察觉的核心代码允许功能测试，**不得为 Markdown/Prompt/Skill/AGENTS.md 等文本型文件创建、保留或运行模拟会话行为测试或任何对应的测试文件**。
