# Skills CLI 并行启动失败的恢复案例

观察与恢复验证日期：2026-11-22。环境为 macOS、T3 Code 会话中的命令行工具调用；成功恢复使用 `skills@1.5.18`。Node 与 npm 的当时版本未保留，不据此扩大版本适用范围。

## 实际现象与证据

一次 Skill 研究任务并行启动五个 `npx skills find <关键词>` 命令，五个均失败。工具结果包含 `ENOENT`、`ENOTEMPTY`，错误路径指向同一个 npm `_npx` 缓存目录。路径已泛化，原始会话与日志不随公开案例发布。

随后在独立临时目录串行准备 `skills@1.5.18`，准备完成后直接调用该目录中的 CLI，再并行执行检索，查询成功。临时安装和本次临时文件在研究结束后已清理；未建立常驻安装，也未修改第三方 `find-skills`。

## 已跑通的恢复方法

1. 为本次查询建立独立临时目录，串行完成指定版本的 CLI 安装，确认安装成功后才启动查询。
2. 使用同一个已准备好的入口执行 `find <关键词>`；本案包内入口为 `node <隔离目录>/node_modules/skills/bin/cli.mjs find <关键词>`。入口路径须先按实际安装核对。
3. 准备阶段完成后再并行检索，核查实际返回的候选内容，不能仅以安装成功或进程启动作为恢复证据。
4. 任务结束后仅清理本次隔离目录与临时材料。该方法用于临时研究；需要持久化配置时另选常驻入口。

这里可复用的认识是：依赖准备与查询是两个阶段；共享安装尚未稳定时，同时启动的命令包含安装副作用，不能当作相互独立的只读查询。

## 原因边界与重新核验

共享缓存初始化冲突是候选解释；本次没有单变量对照，隔离目录、准备顺序与调用方式同时改变，不能据此证明 npm 的通用缺陷，也不能断言所有并行 `npx` 都会失败。没有证据表明需要清空用户的 npm 缓存。

本案只验证了上述组合中的恢复方法，未验证其他平台、版本、关键词或已经准备好的 `npx` 路径。遇到相似错误时先核对当前报错阶段、缓存路径及版本；网络、权限或包自身损坏需按实际证据另查。

Skills CLI、Node、npm 版本或缓存配置变化、上游报告相关修复，或同症状再次发生时，重验相关路径。升级只是重验信号，不能直接认定原问题消失；本次保存案例只作静态核查，未重新安装或重放检索。
