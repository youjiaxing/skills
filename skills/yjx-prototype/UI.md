# 视觉与交互原型

本参考用于比较视觉方案或预览选定设计的页面与操作流程。共用的范围、验证和交接规则见 [SKILL.md](SKILL.md)。

## 1. 放入可判断的产品上下文

从用户要完成的任务出发，识别进入原型的入口、周围页面、返回位置和相关状态。已有产品且问题关乎后续页面衔接时，优先呈现真实上下文中的入口、导航和反馈。

局部增量可在相关现有页面上制作，复用适用组件、资源和布局习惯；新功能应展示它将如何接入宿主。整体重构则根据新目标设计结构和视觉，同时表达与保留流程的连接。没有合适宿主时，按项目路由约定建立有明确原型标识的页面或独立演示。技术隔离不等于视觉与流程割裂。

使用目标视口、合理内容密度和能区分归属、权限或状态的示例数据。已有资产适用时优先复用；需求改变的部分由新设计决定，不只套相近配色来表示“沿用现状”。

*完成条件：用户能看出原型在预期产品中的位置，理解变化及保留的上下文。*

## 2. 按实质分歧制作方案

尚在探索不同设计时，选择能表达实质差异的方案数量。让方案在布局、信息层级、主要操作或流程组织上有可解释的区别；只换颜色或文案不足以代表结构探索，但用户确实在比较颜色或文案时，应直接制作该类对照。

比较同一问题的方案使用相当的任务、内容和起始情境，避免以数据差异误导布局选择。共享基础资产可以减少无关噪音；各方案仍应有空间表达自己的设计，不因共用布局而抹平需要比较的差异。

已选定方向、只需确认流程时制作该方向的连贯体验，无需再制造竞争方案。两种任务都认真呈现本次要判断的视觉与交互；尚未展开的部分明确区分，避免用不相关占位页代替关键体验。

*完成条件：每个方案都能回答其设计问题，差异可直接体验，比较不依赖用户想象。*

## 3. 提供便捷比较与连贯操作

多方案提供清晰的名称和便捷切换，支持用户组合不同方案的优点。浏览器中优先使用可分享、刷新后仍能定位方案的入口，例如 `?variant=`，并提供独立于产品设计的切换控件；支持合适的键盘或辅助操作，输入文本时不抢占按键。其他平台采用对应的可重访定位和选择方式，不硬套浏览器参数。

需要底部浮动切换条时，让它与产品 UI 有明确区别且不遮挡要体验的内容。演示选择器仅在原型环境可用，不能随生产构建意外发布。

实现影响选择的点击、展开、表单、导航、返回和状态反馈。确认范围内的关键路径应能实际走通；涉及拒绝、取消、撤销或权限差异等会改变设计判断的分支，一并呈现。用于比较的关键交互可用隔离状态模拟，但不能只弹出一条说明来代替需要体验的流程。

*完成条件：方案容易切换、定位和重访，用户能通过操作比较其差异。*

## 4. 检查并提交体验

实际打开目标页面或原生入口，操作本轮关键交互，检查目标视口下的布局、导航与反馈；记录真实结果及限制。选择器、场景面板和模拟数据应能辨识，且不扭曲用户对产品表现的判断。

向用户提供准确入口以及比较重点。将其选择映射到具体设计内容：可选整套方案，也可组合某个方案的信息层级和另一个方案的操作方式。交付和留存按 [SKILL.md 第 5、6 节](SKILL.md#5-体验反馈与交付) 处理。

*完成条件：用户能直接体验当前版本并给出具体反馈，确认结果能被后续实施准确承接。*
