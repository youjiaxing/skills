# 证据记录与自动审核

建立知识段、主张映射和审核本地草稿时读取。底稿用于核验，课程正文只保留学习所需的证据归属与时间锚点。

## 每集记录

采用能被结构化读取的 JSON 或 YAML，沿用任务已有格式。每集单独保存，原始证据按该集身份归档；共享配置不共享内容证据。

| 记录 | 必需字段与约束 |
| --- | --- |
| `source` | `source_id`、原始和最终 URL、分集、平台内容 ID、语言、时长秒数；未确认字段明确记录缺口 |
| `attempts` | 每条适用取证路径、当前身份、实际观察、结果、失败原因和证据位置；不保存登录凭据或签名链接中的敏感信息 |
| `raw_evidence` | `evidence_id`、`source_id`、类型、原始文件/响应引用、原视频起止秒数；文本包含可定位段号，画面包含截图、截图来源（解码帧/播放器截图）、`selected_quality`、`selected_frame_rate`、`decoded_frame_size`、`rendered_player_size`、`final_image_size` 及观察事实 |
| `segments` | 主文件中的知识段字段，`evidence` 引用一个或多个 `evidence_id` |
| `claims` | 每个核心主张及实际包含的学习目标、操作步骤、关键画面的 `claim_id`、正文位置、主张文本、`segment_ids`、重要性和复核结果；不要求为填字段添加课程模块 |
| `audit` | 当前草稿版本、各检查项的通过/阻塞结果及原因、修订后的复查结果 |
| `delivery` | 本地路径；逐集记录 `delivery.json` 的当前状态、单调状态历史、失败事件和恢复位置；若请求 Notion，记录真实页面 ID、创建/更新方式、内容及状态回读结果，未知状态不记为成功 |

原视频证据类型为 `video_subtitle`、`video_audio`、`video_frame`。`external_reference` 和 `organizer_suggestion` 单独记录，不能作为核心主张的来源。平台字幕即使是 AI 生成，仍需注明轨道类型与质量，不标为人工校对。

重要性按主文件的错误后果标准判断，不按代码、数字等字面类型判断。重要条目的 `verification` 记录核对过的原音频或清晰画面、具体观察和结论；不重要条目标记“未额外复核”，不伪装成复核通过。

对 `video_frame` 证据，除画面技术字段外还必须记录视觉增量：

- `visual_claim`：该画面直接支持的视觉主张；
- `knowledge_segment`：所属知识段；
- `information_added`：相对字幕/音频新增的学习信息；
- `why_text_evidence_is_insufficient`：仅靠文字证据不足的原因；
- `duplicate_of_existing_image`：是否与已有图片重复；
- `keep_or_discard_reason`：保留或丢弃理由。

图片数量不由视频时长决定。审核应检查关键视觉主张是否覆盖、每张图片是否带来新增学习信息，以及是否存在重复图片；纯演讲可以没有图片，短视频也可以因多个独立状态变化保留多张图片。

## 时间与身份

- 起止时间均以原视频为基准，数值有限，满足 `0 <= time_start <= time_end <= duration_seconds`。不确定时长必须先确认，才能通过涉及范围的检查。
- 证据产物状态与界面状态分开审核：已成功导出的字幕、音频或画面文件继续作为证据；一次播放器刷新、跳转或渲染异常只能记录为当前观察失败。对临时异常至少复查同一来源和时间段，或读取已保存产物，不能据此把“当前未渲染”改判为“来源不存在”。
- 软件演示画面审核必须包含分辨率与帧率链检查：请求画质、实际画质、实际帧率、原始解码帧、播放器渲染尺寸和最终裁剪尺寸是否记录并一致。分辨率和帧率分开判断：默认优先实际 1080P，最低最终图门槛为 720P；在选定分辨率内优先实际帧率更高的流，但不把 1080P 自动标成高帧率。登录与画质门禁按主 skill 的“访问门禁与登录态判定”审核。原始解码帧高度低于 720 像素、实际档位低于已声明可达档位，或最终文字不可辨认时，改用合适源重取；无法重取时只能降级为文字转录和观察事实，不能标为“图片与凭据”检查通过，也不能在未说明原因时设置完成状态。
- **截图边界与构图审核**：聚焦裁剪旨在剥离浏览器标签、地址栏、播放列表等外部非视频外壳；只要不遮挡教学核心内容（代码、终端、图表），画面自带的讲者摄像头与原生字幕默认视为自然视频构图允许保留，严禁因未抠除边角摄像头或字幕而判定审核不通过，避免过度微调带来的无谓耗时。
- 登录态审核：检查结论是否符合主 skill“访问门禁与登录态判定”，四种状态没有混写，匿名或外部请求结果没有被当作未登录并据此要求用户登录（否则审核失败）。
- 对转换后的音频核对时长和音轨完整性；片段转写要记录裁切起点，并把局部时间加回偏移。中间裁剪、加速或拼接必须保留时间映射，无法映射时不用该产物生成锚点。
- 字幕或转写段中有较长空白、明显首尾缺失或不连续时，检查是否只是静音、片段下载或截断；覆盖比例不是内容准确性的证明。
- 分集 ID、轨道语言与证据一致。AI 字幕、译文与配音不一致时保留冲突，不只凭文案语言认定匹配。
- 视频演示创建 Issue、PR 等外部写入时，将“预期目标 → 项目配置中的目标 → 返回链接或结果页面中的实际目标”逐项核对。创建了自己的仓库、CLI 返回成功，都不单独证明写到了该仓库。实际命令被折叠或未展示时，保留未知参数，不根据结果反推完整调用，也不臆测目标偏差的唯一原因。
- 共用章节锚点可以减少正文重复，但底稿仍保留逐项主张映射。`00:00` 只在证据确实位于开头时使用。

## 自动审核

这是编写之后的一次独立审核遍次，由 Agent 对照材料完成，不要求用户逐篇审批，也不模拟“新学习者”对话来评估提示词。

按下表记录实际检查结果。结构与时间检查可用 JSON/YAML 解析器执行；语义支持度需要阅读原始材料，存在字段或标签不能替代这项判断。

| 检查 | 通过条件 | 未通过时 |
| --- | --- | --- |
| 来源身份 | 正文、底稿、视频与目标分集一致，语言与时长已核对 | 重新取证；身份不明阻塞该集 |
| 产物真实性 | 原始字幕、音频或画面实际存在并可读取，不是只有路径、菜单或成功响应码；已保存的有效产物不因一次性的播放器渲染异常失效 | 修复获取路径或复查界面；仍无核心证据则报告不足 |
| 时间定位 | 起止时间有效且能对应原视频，片段偏移已换算 | 修复映射；无法定位的核心内容阻塞 |
| 主张支持度 | 每项核心主张及实际包含的目标、步骤和画面引用的原证据真的支持所述内容 | 删除扩写或补取证；影响主要内容可信度时阻塞 |
| 反脑补与事实真实 | 标题、摘要和结论只概括视频支持的内容；作者观点不强化为普遍事实，无生造理论或为格式扩写的图表 | 删除无依据内容，还原证据支持的表述，不以改归属标签放行扩写 |
| 异常与真实现场 | 如实记录操作冲突和失败，原因仅写证据支持部分，未知原因保持未知，无粉饰或推测性防御方案 | 回到证据区分观察与归因，删去无依据解释并保留缺口 |
| 重要内容复核 | 影响结论、理解或主要操作的内容已对照原音频/清晰画面，关键疑点已解决 | 局部复核；疑点未解不能靠置信度或免责声明放行 |
| 来源归属与范围 | 仅处理指定视频，不查引范围外分集；视频事实、作者观点、必要极简释义及可选的整理者设计练习可区分；无视频外方案和模板 | 按主文件“交付边界”收缩内容；外部资料和补充标签不能替代视频证据 |
| 内容清晰与用途 | 在视频明确范围内可理解、可核实、可回看；内容形态适应类型与用途，未指定用途时中性整理；速查卡、自测、学习目标等按需，无视频外独立复现承诺 | 调整表达和结构，恢复视频已讲但被省略的必要信息；视频未交代的前提如实留缺口，不强制补模块 |
| 例子与操作细节 | 例子默认压缩保留，理解及执行视频所示操作所需的条件、命令、参数、配置和结果未因压缩失真；没有无条件转录全部画面或逐行解析 | 对照证据恢复必要细节，删去非必要展开；不另造通用环境替代实现 |
| 文风与回看 | 标题和结论克制，无空泛评价；正文按内容单元沿视频顺序呈现，保留时间锚点，不复刻寒暄和重复表达 | 压缩套话和重复，恢复来源顺序；只作必要释义，不扩写背景 |
| 图片与凭据 | 必要画面在对应步骤就近嵌入，时间、观察事实、视觉增量和主张相符，敏感信息已脱敏；已剥离外部非视频外壳，未遮挡核心内容的自然构图予以保留；正文嵌入顺序与 `visual_coverage.embedded_files` 逐项一致 | 修复或明确复制/嵌入限制并给出有证据的降级内容；同步调整正文图片嵌入顺序或索引 |
| 三方一致性 | 课程正文图片、`visual_coverage.embedded_files` 和磁盘聚焦图数量、顺序、文件名一致；请求 Notion 时回读图片再次一致 | 运行 `validate-course-artifacts.mjs`，修复不一致后再写入或回读 |
| 链接 | 普通来源链接与手动时间清楚分开，标作可跳转的深链已实际验证 | 改成时间文本与普通来源链接 |
| 独立审查员终审 | 外部写入或交付前，必须唤起独立只读审查子代理（Auditor Subagent；Start every subagent with a fresh context window (do not fork the current conversation). 宿主不支持时由当前代理做一次同标准的正常审查，并在 `delivery.json` 的 `audit` 记录 `method: current_agent_review` 与 `reason`）对照原始字幕、清晰截图与草稿开展实质审查，确认范围、主张、例子及必要操作细节忠实于视频，未扩大解释或保证 | 修复全部实质性缺陷并重新复核，未通过时严禁外部写入或标记完成 |

### 独立审查员终审流程与一票否决机制

本地自动化格式校验仅保障语法、路径与图片数量等物理约束，不能证明内容忠实、清楚或适合用途。

交付或外部写入前的终审流程如下：
1. **审查方式**：宿主支持时启动只读子代理作为独立审查员（Course Auditor；Start every subagent with a fresh context window (do not fork the current conversation).），传入原视频全量字幕、证据索引 `evidence.json`、聚焦截图与草稿正文；宿主不支持子代理时，由当前代理对照同样材料做一次正常审查，不需要额外隔离仪式。两种方式都在 `delivery.json` 的 `audit` 记录 `method`、`result`、时间（`current_agent_review` 另记 `reason`）。
2. **实质审查**：按上表对照主文件的编写边界，重点检查：
   - 是否添加视频外方案、生造理论、拔高结论或强制课程模块；
   - 是否对异常推测原因、粉饰事实或扩写防御建议；
   - 是否轻率删例子，或压缩损害了必要条件、操作参数与结果；
   - 是否扩大指定视频范围、改变讲解顺序或使内容难以按时间回看。
3. **一票否决**：只要存在实质性偏差，审查员出具缺陷清单并一票否决。主 Agent 必须回归草稿重构修复，直至重新复核清零后方可放行。

审核通过只允许进入下一交付步骤，不证明 Notion 已写入。写入与外部后置核验遵守 [Notion 交付](notion-delivery.md)（并发上传图片、一步创建页面并单次回读核验）。

`delivery.json` 是逐集恢复的事实来源。每次中断或失败都追加不含凭据的事件，恢复时从最后一个已验证状态继续；运行 `node scripts/validate-delivery.mjs <delivery.json> <输出目录>` 失败时，停止该集的外部写入或完成标记。

## 阻塞报告

逐集报告已确认的身份、尝试过的适用路径、实际失败原因和缺失证据，并说明恢复条件，例如用户登录、安装获授权的工具、提供可用音频或修复数据返回。当前工具不能取证不等于原视频不存在内容。

不生成推测性课程目标或步骤；外部参考只能标为参考链接，不能用来填充缺失的视频讲解。保留已确认且脱敏的底稿，便于恢复，不因后续失败声称前序取证也已失败。
