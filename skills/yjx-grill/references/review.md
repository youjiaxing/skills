# 独立评审

正式对齐方案在请求批准前必须评审。直接结论仅在实际风险、可逆性、权限、数据、兼容性、安全或项目治理要求时评审；评审本身不自动把它变成正式方案。

## 派发

宿主提供原生子代理时，使用与方案形成独立的审阅者，只给本次材料，不继承当前对话：Start every subagent with a fresh context window (do not fork the current conversation).

派发开头明确：接收者已经是独立审阅者，应直接审查并返回自己的发现。权限只读，不得再委派、创建/分叉会话或发消息。不能完成时向主代理说明限制，不自行改换工作流。禁止另起外部 CLI 或用普通对话假装子代理。

提供原始目标、核实事实、候选结果及必要内部记录，涵盖来源与证据、项目参与约定、确认范围、待定或受约束事项、已选方案/代价、被拒分支和剩余假设。审查应验证正确性、适用性、可维护性、兼容性、代价与真实来源，不凭偏好重开已决方案。

## 等待与降级

单次启动/等待超时不等于评审终止。排队或运行中的任务保留，按宿主完成通知、有限时长等待或续接机制处理，不另设固定总时限、不短周期轮询、不重复派发。宿主要求结束本轮等待通知时照做，不能因此取消原任务。

启动结果或状态不明时，通过可用只读入口核实并披露限制；不能猜评审已完成或失败。只有明确失败、宿主终止、确实无法继续或用户要求停止时才结束等待。取消与清理服从宿主规则。

没有可用子代理或调用明确失败时，仅当项目与宿主允许，才由当前会话按同一标准自审，并在呈交结果时说明原因。若独立评审不可替代，则保持未完成，报告具体阻塞，不能用自审绕过。

## 发现闭环

有效发现须有具体证据和实际后果。主代理解决有依据的发现，并核对实际修改与验证结果。局部明确修正、未引入新权衡时由主代理核实；改变方案结构、核心契约或新增权衡时，才对修订范围针对性复核。

需要同一审阅者跟进时保留它，发送增量材料；确认无需跟进后再关闭，避免先关闭再恢复。新的人类决策分叉退回讨论。有证据的实质正确性缺陷未解决，或不可替代的独立评审未完成时，暂停请求批准或交付。
