# HyperFrames 工作方法

使用 HyperFrames 合成、复用组件或排查预览与成片差异时读取。本参考按本地 CLI 0.9.53 与[固定上游来源](sources.md)核查；其他版本先核实命令和实现，不自动升级。以下没有要求执行上游的账号、生成、反馈上报或遥测流程。

## 从当前项目入口继续

1. 找到项目已认可成片、生成它的配置和构建入口。沿真实配置分支追踪到调用函数；区分正式使用、历史试验和仅导出未调用的函数。
2. 读现有时间轴与素材清单，确认帧率、镜号、原声、字体及媒体路径。把表演时点和阅读窗口落在已有数据里；项目已锁定的字幕/声音/布局优先。
3. 只对本次授权的修改范围操作。冻结目录保留，准备与渲染另用版本；自包含素材用独立副本，硬链接不能隔离原位覆盖。

## 可独立跳帧的动画

- 可见状态由时间决定；使用暂停的 GSAP 时间轴，构建完成后注册到对应 composition id。字体测量在加载后完成，媒体使用项目内相对路径。
- 同一属性由一个时间轴负责；GSAP 控制的 transform 与 CSS 初始 transform 分开处理。多次 `fromTo` 检查 `immediateRender`，验证前进、后退和直接跳到同一时点的状态一致。
- 程序效果用纯时间函数或有种子的确定计算；读取属性更新的实现要验证 seek 路径，不能假定实时播放触发的回调在逐帧跳转也触发。
- 推拉、冲击作用于舞台包装，字幕与出处保持项目约定的屏幕锚点。短冲击前后检查回稳与画面边缘，不能把持续手持预设当作对白默认效果。

## 复用组件前检查实际交付文件

新增特效、转场或数据展示时，按名称发现已安装的 `hyperframes-registry` Skill，依项目本地CLI入口检索与接入；未安装时说明缺失，不自动补装。先按用途用英文检索，画面文字沿项目语言。普通词匹配与需额外下载模型的语义检索是两条路径，后者须有对应授权。

选择具体名称后再处理依赖、写入位置和版本，不按tag批量添加。Skill固定版本不代表注册表内容固定；默认注册表可能跟随main，组件也要记录实际来源。安装Skill不等于下载全部组件，更不证明所选组件可用。搜索未命中时按项目边界记录缺项，不自动发送上游反馈。

注册表的宣传预览不等于可直接嵌入的组件。先读具体 HTML 的挂载说明、样式、脚本和依赖，识别它是独立 composition 还是并入宿主的片段，再核对变量、时长、默认素材、ID、字体和许可。具体实现优先于笼统的 block/component 名称。

- `camera-shake`：源码提供纯时间噪声、overscan 防露边和 seek 可触发的属性 setter；默认持续手持运动。借鉴算法和边缘检查，不直接启用到普通讲话。
- `beat-freeze-cut`：是带固定场景内容和切点的宣传片，不是通用角色反应模板。只参考冲击、保持、退出的分段结构。
- `caption-editorial-emphasis`：按英文词时间轴生成强调字幕，包含不同字体和自动缩字。只参考边界、显隐和溢出处理，中文正式字幕沿用项目组件。

以上三个条目已读源码，未在本项目挂载渲染，不声称外观或兼容性通过。注册表组件需用时再选，依授权验证实际输出；本参考不触发安装。

## 资产复用的范围

借鉴 `media-use` 的候选列表、内容哈希、来源和真实尺寸/时长记录。语义相近仅作为候选，按角色、服装、场景和项目授权判断可用性；同一提示词命中缓存不证明素材适用。

上游会自动把素材复制进全局缓存，默认位置在用户目录；实现支持 `HYPERFRAMES_MEDIA_HOME` 覆盖。接入前核对项目媒体根与实际写入范围，外置盘项目保持既定存储边界。仅整理经验不需要运行 `resolve`、`adopt` 或下载服务，也不另建全局素材系统。

## 从参考片段学习，按可编辑范围迁移

- 学习切点、换稿或短促特效时，在连续原帧中找进入、峰值、保持和退出；参考本来是硬切，就按帧切换，不擅自补淡化。只取节奏或实现方法时，不把逐像素复刻设成目标；不得为匹配参考自动重录声音或生成角色视频。
- 真正迁移外部动画工程时，先区分元素可原生编辑、保留原绘制代码并由宿主驱动时间、或只能作为渲染视频剪辑三种范围，再选方式。记录近似与丢失项；源码扫描无警告不证明能无损迁移。像素对照服务保真目标，不作为喜剧自然度或笑点质量的评分。
- 系列模板可参考分镜、粗稿和验收的顺序；模板自己的音色、配色、组件、切镜密度及停留时长不自动成为当前项目标准。需要某类参考时才读其决定性材料，不因借鉴方法安装整套服务流程。

这些是外部候选方法，来源与已读范围见[来源记录](sources.md)；没有新增同条件成片或成本验证。

## 按真实镜头检查

- **技术检查**：用项目入口执行 `check`，查看浏览器审计是否真正运行、覆盖哪些时间和哪些警告被保留。命令成功与画面自然是两个结论。
- **画面检查**：取每个叙事镜头的有效起点/中点、切点两侧连续帧、文字的小屏版本；爆点和过渡补连续原帧，实际 MP4 对照原声检查。固定抽样偏移仅为起点，超短镜头按真实帧范围调整。
- **抽帧边界**：0.9.53 的 `snapshot --review` 从时间轴顶层 timed graphics/video 条目推导场景；穿透普通包装后，绘稿曝光和未标轨道类型的字幕也可能成为条目。先对照项目镜号/镜头区间，不能把每次嘴态换图当切镜，也不能把自动图表当完整审片覆盖。
- **局部返修**：记录“时间、位置、观察到的问题、具体修改、保持项”。修后复查受影响窗口及相邻切点；共享组件或全局配置变化需覆盖全部使用处。只有新增失败或未解决风险才扩大检查，不为每个局部修正重做整片。
- **观察方式**：简单一次性读图可由主代理直接查看；持续视频/素材识读值得隔离时，按名称发现并调用已安装的 `yjx-image-reading`，由它准备输入并执行只读观察。保留主代理对获取来源、授权、覆盖范围与结论的责任。需要独立审查时，Start every subagent with a fresh context window (do not fork the current conversation).

官方 `check`、项目核验脚本和 `snapshot` 会写报告、日志或图像。文档维护用只读代码检查、链接检查和哈希比对，不为证明文档修改而重跑制作脚本。冻结前后证据要另存，不能依赖工具管理的缓存永久保留。
