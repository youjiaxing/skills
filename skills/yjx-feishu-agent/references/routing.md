# 公共群的引用路由

同一机器人可接收多个 Codex 会话的推送。仅在明确选择的已绑定群启用 `quoteRouting:true`：白名单用户直接引用消息并 @机器人时，交给该消息登记的来源会话；未引用时仍使用该群原有 `threadId`。普通群保持单会话路径，不提供新建、停止或管理其他会话的远程指令。

## 来源与投递

出站 send/update 显式提供 `sourceThreadId`，由已授权的本机调用方取自实际 Codex 会话标识。它不是从消息正文、标题、最近聊天或群默认会话推断的，也不是授予群成员访问所有本机会话的入口。群用户白名单和明确 @ 条件保持不变。

来源映射按应用、群、飞书消息 ID 隔离，存于仓库外 `message-routes-v1/<app hash>/<chat hash>.json`。同一卡片由最近一次成功发送或更新它的会话负责；源字段与投递请求一起保存，成功后发布映射。未携带来源的旧投递继续支持 status/去重，但不能引用路由；不扫描历史猜测来源、不改写旧请求指纹或重新发送。需要历史登记时先在本机核对原请求及真实来源，当前命令不提供任意消息 ID 导入。

更新前先设置路由 pending；远端成功而本地记账未完成、提交结果未知或来源存档损坏时，新引用保持待核查，不使用旧来源或默认会话兜底。已有成功 acknowledgement 可通过 `outbound.mjs reconcile` 修复本地投递和来源；此过程不发消息。旧记录没有来源时无法由恢复命令补猜。明确未提交的更新可恢复原映射，原失败证据保留。

## 受理与继续追问

直接引用的消息 ID 是唯一选路依据，不沿祖先查找另一会话：某张卡片由 A 更新为 B 后，新引用卡片交给 B；直接引用此前 A 的回复仍交给 A。话题客户端若仅提供根消息 ID，就只能按该根消息登记的来源选择，不声称能辨认未提供的最近回复。

入站受理与出站更新共用群级锁；受理时读取并持久保存目标后释放锁，后续卡片更新不改变已经受理的目标。锁忙、映射缺失、冲突或待核查不提交给其他会话；映射缺失会回复简短提示。重复事件按原入站编号去重；重启不重放队列或未知请求。

成功回复记录实际飞书回复 ID 和同一来源，供继续引用。若回复已送达但来源记账失败，保留回执和未决记录，不重新发送回复；来源缺失时提示核查。本机原有群消息按需查询接口保留，自动近期群历史已取消，见 [上下文](messages.md)。

## 归档与不可用

仅这条已确定来源的引用请求允许自动解归档。先取得原会话锁，检查目标明确为 archived，持久记录恢复意图，调用 `thread/unarchive`；返回 ID 必须一致，再用 `thread/read` 确认活动状态，才提交这次追问。响应丢失、接口不支持、仍归档或读取失败均不提交、不自动重放、不新建或换会话。恢复后保留活动状态，不自动重新归档。默认绑定请求仍沿用原归档阻断规则。

这是接收器内部的限定能力，不新增通用 agent CLI 的自动恢复开关。实际 Desktop 专属工具、会话锁及审批限制沿用 [Codex 接入](codex.md)。

## 启用与回滚

先核对用户选定的公共群及已有默认目标。以下命令均可附 `--state-dir PATH`；变更前接收器须停止，命令共用应用锁并保存配置前后快照。

```text
node skills/yjx-feishu-agent/scripts/receiver.mjs stop
node skills/yjx-feishu-agent/scripts/bindings.mjs quote-routing --chat oc_GROUP --enabled true
node skills/yjx-feishu-agent/scripts/receiver.mjs start
```

停服后用 `--enabled false` 恢复该群单会话规则，保留来源、投递及入站记录。代码升级本身不自动选择或启用公共群；切换前检查当前未决请求。验收包括 A/B 来源、卡片更新换来源、旧回复继承、无引用默认目标、归档恢复、跨群隔离、未知更新阻断和重启去重。协议/状态测试通过不等于已完成实际飞书到 Desktop 的往返验收。
