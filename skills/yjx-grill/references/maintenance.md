# 维护说明

评审、修改或重新设计本技能前阅读；普通执行不加载。运行规则以 `SKILL.md` 及其明确指向的专题为准，本文件解释设计取舍，不再复制整套执行检查表。

## 必须保留的设计边界

**先理解问题，再决定问什么。** 用户给出的方案可能只是补救手段，Agent 的专业判断也不能替代用户的核心意图。以真实经历和证据恢复目标，推断保持可纠正；证据已足够时不加固定问卷。

**意图和后果分别决定参与。** 即使容易撤销，核心意图或项目保留事项仍可能需要用户决定；有多个技术实现也不代表必须提问。提问与正式批准是两个独立判断，不恢复“所有问题一律审批”或“只有不可逆才提问”。

**来源和批准分别记录。** 用户认可一组方案，不会把其中的 Agent 推断变成用户要求或已验证事实。未确认事项保持待定；确认范围、实施授权和开始执行也不能相互替代。

**切片用于完成工作。** 切片之间先识别真实依赖；有前置条件未定的问题不进入当前讨论。一个回答只解决它覆盖的选择，当前切片收敛后还要检查剩余范围。不得为了满足目录、编号或访谈形式制造问题。

**证据不足时先补证。** 核查当前实际命中的入口、配置和底层能力，不凭死分支或旧封装推断系统限制。沿用既有有效约定，不把单次方案确认扩大为永久放权。

**呈现服务判断。** 问题本身可独立理解，解释和结论直接回答；建议、背景和执行选项用不同层次呈现。视觉或高成本创作的关键判断需要可感知的中间产物，不能仅用字段清单和抽象方案替代体验。

## 文档职责

| 文件 | 负责什么 | 何时加载 |
| --- | --- | --- |
| `../SKILL.md` | 讨论主循环、参与边界、来源覆盖、完成与实施交接 | 每次执行 |
| `discovery.md` | 含糊意图、复杂事实调查、表现前提和指定载体 | 命中对应情形时 |
| `review.md` | 独立评审、等待、失败降级和发现闭环 | 正式方案或风险要求评审时 |
| `contract.md` | 正式方案的精度、呈交和批准选项 | 需要正式批准时 |
| `history.md` | 上游来源、已做比较及重要演进依据 | 比较上游、重开旧取舍或查历史时 |

普通执行不加载维护和历史。只在历史能改变当前维护判断时读取有关记录，不要求每次全文回溯。跨技能调用使用注册名和宿主发现机制，不硬编码其他技能的安装路径。

## 修改与验证

先读取已安装的 `writing-for-agents`，遵循仓库[跨技能调用约定](../../../AGENTS.md#cross-skill-invocation)。按信息层次组织内容：所有分支都需要的规则留在入口，只有特定分支使用的细节放在带触发条件的指针后。同一含义只维护一份，修改职责边界时同步检查入口和引用。

评审时重点检查：

- 原有的零问题路径、核心意图提问、项目保留事项和风险判断仍能分别工作。
- 每个范围内事项都有依据充分的处理结果，局部同意不隐藏剩余事项。
- 新位置上的规则仍有明确加载条件；正式方案、直接结论及风险评审路径均未断开。
- 授权、持久化、独立评审、等待和失败降级保证没有因压缩而削弱。
- 文档组织与展示调整没有夹带新业务范围、审批门槛或工具依赖。

遵循仓库[技能验证政策](../../../AGENTS.md#skill-verification)：文档修改只做静态审阅、链接和一致性检查，不创建或运行模拟会话、提示词行为测试。实际用户交互可以用于复盘，但静态检查不证明模型可靠执行、视觉效果或跨宿主触发已经验证。

历史只记录影响后续维护的取舍、来源和适用边界；已成为运行规则的内容不再逐次展开为完整检查表。新的单次失误先判断是否违反已有规则，避免每次复盘都追加一段同义禁令。
